Author: `SkepticM`. Read: `CHARTER.md`; `innovator.md` in full; `m1` §2-4, `m2` §2-6, `m3` §0/§8-10, `m4` §0/§2-4; `CAPABILITY-MECHANISMS` §3-4; `REJECTION-DEEP-DIVE` D14; `RL-DESIGN` S0-S3. Two abstract fetches: ExPO 2507.02834 (sets **no** numeric threshold on p(answer | explanation) — P5's 0.05 bar is M1's, not ExPO's); Re-Prefill 2605.12549 (abstract does not characterise failure-case attention as multi-peaked — P4's premise is unsourced at that level). Everything else is from the surveys' `[V]` rows and the project's `[P]` numbers. No GPU.

Summary verdicts: **P2 PROMISING** (with three fixes), **P1 MAJOR**, **P5 MAJOR**, **P3 MINOR as instrument / MAJOR as reward**, **P4 MINOR as diagnostic, not a bet**. The innovator's best move was P2; his weakest was the unlock-curve design, which as written cannot tell capability from reading a tick table.

## 2. Specific checks

| check | finding | what must be added |
|---|---|---|
| (a) P1 unlock curve: pass@8(none ∣ full block) | Format compliance, not capability: the block already states every candidate fails, so `none` is the only consistent next token — a text rule ("all rows have ✗ → none") that the grey image cannot separate at ρ = 1. The informative rows are ρ ∈ {0.25, 0.5} restricted to items whose deciding row is *not* in the prefix; for negatives that means every remaining row must get a ✗ on the flipped clause from the image. MFC's smooth curve (2.2 → 34 → 85) is the prediction; a step function (flat below 1, jump at 1) kills the family before ρ = 1 is even read. | Leak-stratified rows; grey-image verdict agreement on the model-written rows at ρ = 0.5 (must be at chance); the ρ = 0 block on the 4B Instruct with Acc@0.5, Acc@0.9, Rejection and false-null all reported. |
| (a) withdrawal schedule must show | Three curves per checkpoint on a *held-out* unsolved set (training items are memorisable — PrefixRL's own warning): pass@8 prefixed at current ρ; pass@8 unprefixed under the block protocol; pass@8 unprefixed under the plain prompt. Hint reliance = 1 − unprefixed/prefixed on the same items. Unsolved-set conversion = base pass@8 = 0 (plain prompt) → pass@8 > 0 unprefixed, plain prompt, held-out. | The per-item ρ histogram over training (MFC's frontier) and the forced-drop count, so "annealed to 0" is shown rather than asserted. |
| (a) enumeration recall | Measured nowhere before training: the curve uses SAM 3 candidates; the ≥ 85% guardrail is checked only during RL. At deployment under the block protocol the policy enumerates; under the plain prompt it never does, so the plain-prompt claim does not depend on it, but the block-protocol claim is capped by it. | ρ = 0 enumeration recall of the policy vs SAM 3 instances (area ≥ 0.2%) on the dev half, by category and instance count, before any training. If < 60% the block protocol is a detector-in-disguise claim. |
| (a) is a ≤ 60-token block immune to the thinking cost? | Not established. The 8B 61.3 → 52.5 drop may be a prior shift (Rejection up / Discriminative down, the 2:1-SFT signature) rather than a length cost, and the block ends with a live `none` option — exactly that prior. Perception-R1's −14 was free-form; the structured-short-block vs free-form comparison "has never been run" (M2 §5). | The ρ = 0 row is the right test only if it reports false-null and Rejection next to Acc@0.5, on 4B and 8B. |
| (b) P2 on-policy box strings | Not on-policy under the plain prompt: the outline prompt is a different task whose box may be the drawn rectangle. Gate 3 already holds the on-policy wrong box; a short unique expression gives the on-policy right box. | Replace outline prompting; keep the IoU ≥ 0.5 check on both. |
| (b) does DPO on coordinate tokens compare objects or digits? | Digits: the sum-of-log-prob difference concentrates on the first divergent token (x1's leading digit), so the contrast is on 1-3 tokens of *where the box starts*. It is "which object" only if the readout is object-conditional — which is the experiment. The fallback "restrict to the last two coordinate tokens" is the wrong end: those are conditioned on the divergence and carry little. | A first-divergent-token variant and an answer-index variant (P1's block) as the clean "which object" arms. |
| (b) does the mDPO anchor stop coordinate drift? | No. It stops π_θ(b_T ∣ e_T) falling below the reference (the chosen-likelihood-collapse failure). ## 4. What the Innovator missed

| missed | source | why it matters | cost |
|---|---|---|---|
| **SFT-on-the-block control arm** | M2 §2.1, M3 §9-C, M3 §8-1 | Rex-Thinker's +13.8 came from SFT on answer-conditioned per-candidate traces; the "SFT collapses" evidence (POPE 13.6 → 2.0) is math, and GroundingME's collapse was a ratio effect (1:8 kept positives). Without it P1's headline cannot separate "prefix RL" from "any exposure to the block". Rejected by the innovator on the wrong evidence. | ~2 GPU-h |
| **Inpainting as a test-time instrument and none-rollout source** | M4 §4-6 | Remove the chosen object with LaMa and re-ask; a model that re-boxes the next sibling at p > 0.999 was not evidence-driven. Training-free, uses the existing engine, and the removal chain that ends in an empty scene is a *samplable* `none` trajectory — off-policy guidance with a direction, which S3's forced constant lacks. Nobody has it. | ~1 GPU-h |
| **Clause-level cycle-consistency reward** | M4 §4-2 | Describe the outlined candidate without the expression, compare clause by clause: a graded negative-side reward that needs no construction truth. P3 half-does this as QA; the speaker form has no answer prior. | 1-2 GPU-h zero-shot |
| **Thinking checkpoint + SoM candidate list on GME Discriminative** | M2 §5 | The cheapest test of whether enumerate-then-verify helps this model family at all, before building a block format around it. | 0.3 GPU-h |
| **1:8-ratio SFT's GME-Rejection value** | M3 §8-1 | "The cheapest unanswered question in the table"; could reframe the rejection side. | ~1 GPU-h |
| **Full-parameter lr 1e-6 arm** | `CAPABILITY` §4 rule 3 | The cheapest forgetting defence in the literature beat LoRA on both axes; every headline here is LoRA r = 32. RunPod only at 4B. | one arm |

**The strongest reason the whole guided-prefix family may fail on grounding specifically.** In math the prefix and the answer are the same kind of token: a partial proof constrains the rest, and the base already samples the remaining steps on partial prefixes (MFC's smooth 2.2 → 34 → 85). In grounding the answer is one coordinate token whose value is fixed at prefill (`CAPABILITY` §3; Re-Prefill), the block is a cross-family text format the base has never emitted, and its ticks can be filled from the expression's wording (D14, 0.92). A partially written block is therefore not a partial *visual computation* but a partial *document*: the model can complete the document without moving the selection it was meant to change. PrefixRL's cross-family transfer was Qwen-for-Llama *math text* — same modality — and says nothing about a structured verdict table. The observable signature is a step-function unlock curve, grey verdict agreement above chance at ρ = 0.5, and hint reliance > 0.7 at the end; all three are readable in week 1 if §2(a)'s rows are added.
