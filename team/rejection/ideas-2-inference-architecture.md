### 0.1 Rules applied to every idea below

1. **Every rejection number ships four columns**: literal-`null` rate on the 201, parse-failure rate, false-null rate on the 804 positives stratified by dimension × `size_bin` (and Limited/Small separately), and the 201 stratified by sub-axis (Appearance / Component / Text / State) × length bin (≤20 / 21–35 / >35 words). 201 items → CI ≈ ±6; anything under ≈ 13 is indistinguishable from 0 `[P: CAPABILITY §7]`.
2. **Primary discrimination contrast is absent (201) vs Discriminative-present (204)** — same image source and expression style, no visibility confound (p(null) there is 0.468) — and the deployment contrast is vs all 804. Reporting only the second lets a visibility scalar look like an absence signal in the wrong direction.
3. **Deployable stop rule**: any threshold is set on data that is not GME (removal controls, held-out positives, arm-A negatives) and then applied once. Cross-validated numbers on GME itself are reported as **ceiling, not deployable**. No oracle selection (2606.13156).
4. **Three disguise controls** on every score: (i) *visibility*: Spearman with GT area on positives, and AUROC absent-vs-Limited/Small must not fall below 0.5; (ii) *class presence*: score on class-absent negatives (pilot REMOVE, 316) vs on attribute-false negatives with the category present (arm-A N0 flips or GME) — a class-presence detector is high on the first and ~0.5 on the second; (iii) *artifact*: score on CONTROL_OBJ vs ORIGINAL must be ≈ 0.5 and on not_clean-REMOVE vs clean-REMOVE ≥ 0.8 `[P: tables/pilot_abstain*.jsonl]`.
5. **Hardware**: local = RTX 5090 32 GB VRAM, 23 GB host in WSL (`wsl -d Ubuntu`), one model resident, images streamed. Timing basis: 1.4 s/item decision-token pass at 8B `[P]`; free 64-token generation ≈ 2–3× `[LIKELY: 64 tokens vs 1]`; thinking 20–40× `[LIKELY: diagnosis §8]`; eager attention ≈ 1.5–2× `[SPECULATION]`. 8B bf16 ≈ 17 GB weights, 20–22 GB with image tokens; host ≈ 18–20 GB during load `[P: diagnosis §8]`.

## Idea 1 — Mid-layer absence probe at the decision, prefill and clause positions, then gated difference-in-means steering

**Mechanism targeted**: D1 (is it read-out or representation?) on hard negatives; secondarily D7 (does the representation improve with scale while the score stays 0). Assumes Dispute A is *testable by the probe* (probe AUROC reported per sub-axis × length); assumes Dispute B resolves to negative type (the probe reads before any format is emitted, so format is out of the loop by construction).

**Method.** One forward pass per item with `output_hidden_states=True`, storing the residual stream at all 37 layers for four positions: (a) the decision token (the state that produces the ` null` / ` [` logits after the model's own greedy prefix `{"bbox_2d":`), (b) the last image token, (c) the last expression token (end of prefill, before any decode — the position 2605.12549 and 2605.21954 say already holds the grounding decision), (d) the mean over image tokens (a SAM-3-style global presence read-out). Train logistic-regression probes and difference-in-means directions per (layer, position) on three training sources of increasing type-match — S1 class-label removals (316 REMOVE vs 316 CONTROL_OBJ, OpenImages, category gone), S2 GME removals (333 REMOVE vs ORIGINAL, expression fixed, object gone), S3 arm-A N0 clause flips from the RL-design S0 (≈200–500 pairs, category present, one clause false, images not in GME) — and evaluate each on GME absent-vs-Discriminative-present, then vs all 804. The S1→S2→S3 ladder measures transfer *across negative type* directly. Then take the best (layer, position, source) direction, add α·d at that layer with a gate: steer only when the probe score exceeds a threshold set on S1 controls at 0 false-null (CR-VLM style, 2602.07013), decode with the harness prompt, and report null rate on 201 / false-null on 804 / parse failures. A within-GME 5-fold CV probe is run and reported once as the ceiling.

**Closest prior work and delta.** TRAPSBench `[VERIFIED: 2608.13167]`: Qwen3-VL-8B probe 0.91 vs behaviour 0.29, one-layer steering → 75 % abstention — video physics, hidden-state probe, no coordinate output. 2509.22449 `[VERIFIED]`: difference-in-means unanswerability direction; steering at α = 2 abstains on 95 % of answerable inputs (indiscriminate) — text QA. CR-VLM `[VERIFIED: 2602.07013]`: gated refusal steering in VLMs, over-refusal 0–12 % — task-scope refusal, not absence. Textual steering vectors `[VERIFIED: 2505.14071 abs]`: mean-shift steering improves spatial/counting VQA — no absence task. Delta: first probe/steering on a coordinate-emitting MLLM for REC absence, at the decision token *and* the prefill positions, trained across a negative-type ladder ending in attribute-false negatives, with the three disguise controls and a gate calibrated off-GME. Survey C §3.3 names this as "the experiment nobody has run".

**Kill experiment.** *Decides*: whether the residual stream anywhere carries an absence signal on L4 negatives that a linear read-out can reach. *Headline claim* (paper): "absence is represented but not emitted" — only if S3-trained OOD AUROC ≥ 0.75. *Precondition / instrument-only*: the probe is the diagnostic every training arm is re-run through (does training move the representation or only the read-out?). *Pre-registered stop rule*: if with S3 training no (layer, position) reaches AUROC ≥ 0.65 on absent-vs-Discriminative-present, and the within-GME CV ceiling is < 0.75, the read-out story is dead on hard negatives: rejection needs supervision that changes the representation, and Ideas 3–4 lose their "the information is there" premise. Steering is run only if the probe passes; steering stops if at the calibrated gate the null rate on 201 is < 10 % or false-null on 804 > 5 %. *Cheaper decisive variant*: S1 + S2 only (data already on disk), decision token + last-expression token only, no steering: 0.8 GPU-h, answers "is anything there before the LM head" and the S1→S2 transfer.

## Idea 2 — Per-candidate, per-clause verification with set logic (propose-then-verify), and the isolation-vs-integration decomposition

**Mechanism targeted**: D2 (partial-match acceptance / no clause verification) — is the per-clause check *available in isolation* and only *unintegrated* into the box decision, or does it not exist? Secondarily D3 (a per-candidate score built from clause scores). Assumes Dispute A resolves to sub-axis: the prediction is written per sub-axis (Text verifiable, Appearance/State not). Assumes Dispute B: the yes/no format alone is ≈ chance for the *whole* expression (P4); the hypothesis under test is that per-*clause* yes/no per *candidate* is not.

**Method.** (1) Decompose each expression into head noun + atomic clauses with a text-only LLM (RL-DESIGN's `expr_decompose.txt`, Qwen3.5-9B or API, no image; ≈ 6 clauses per GME expression). (2) Enumerate same-head-noun candidates: primary = SAM 3 with the head noun as text prompt (≈ 5 GB, pinned); secondary = the model's own multi-box answer to "output every <head noun>" (no detector dependency; tests P7's "protocol swap" rule). Report enumeration recall on the 804 positives (does a candidate cover the GT at IoU ≥ 0.5?) before anything else. (3) For each (candidate, clause) ask the policy "Look only at the region outlined in red. Does this statement hold for the outlined object? <clause>. Answer yes, no or unclear" (RL-DESIGN `verifier_clause_instance.txt`, full image with a drawn outline; crop as ablation), and read p(yes) / p(no) at the answer token. (4) Set logic: candidate passes iff every clause has p(yes) > τ; zero passes → `null`; one → its box; k > 1 → the highest min-clause score (or `null` if the RL-design's multi-target reading is adopted). **Isolation test** (the number that decides D2): on the 201, evaluate the clauses against the model's *own emitted box* (the candidate it accepted); on the 204 Discriminative positives, against the GT box. AUROC of min-over-clauses p(yes) (negatives low) is the isolation statistic; on arm-A N0 flips (flipped clause known) also report per-clause identification accuracy — which clause is flagged. Cross-family row: Molmo2-8B as verifier on the same (candidate, clause) pairs, to separate "Qwen cannot verify" from "the clause is not verifiable from the image" (GroundingME's human check is 91 % on 100 items `[VERIFIED: 2512.17495]`, so humans can).

**Closest prior work and delta.** RefBench-PRO Table 5 `[VERIFIED: 2512.06276]`: whole-expression yes/no on the same hard negatives ≈ chance. T/F verification `[VERIFIED: 2509.09958]`: per-box True/False with a frontier VLM, whole expression, RefCOCO only, no negatives. Rex-Thinker / CRS `[VERIFIED: 2506.04034; 2502.20104]`: per-candidate verification *trained* (HumanRef 68.2; FineCops 62.3). FINER `[VERIFIED: 2603.17662]`: clause count is the difficulty dial in VQA. Delta: per-clause × per-candidate, zero-shot on the deployed policy, with the isolation-vs-integration decomposition on L4 negatives by sub-axis, enumeration recall reported, and a cross-family verifier control. Rex-Thinker's number says a trained pipeline reaches 68 on L2; nobody has reported what the untrained checks are worth on L4.

**Kill experiment.** *Decides*: whether the false clause is detectable by the model at all when asked directly about the object it boxed. *Headline claim*: "the check exists, the integration fails" (paper-grade if isolation AUROC ≥ 0.75 overall and the set-logic pipeline gives Rejection ≥ 25 at false-null ≤ 10 %). *Precondition / instrument-only*: isolation AUROC per sub-axis becomes the **verification-capability metric** tracked across RL checkpoints (if Rejection rises but per-clause accuracy does not, the policy learned a switch, not verification). *Pre-registered stop rule*: if the Text sub-axis isolation AUROC is < 0.70 (the easiest checkable clause on an OCR-strong model), the check does not exist zero-shot, the training-free pipeline is dead, and the training design must teach verification itself, not just the null output. If Text ≥ 0.80 but Appearance / Component / State < 0.60, the pipeline is Text-only (≈ 50 of 201 items = ≤ 25 points ceiling) and is reported as such. *Cheaper decisive variant*: Text sub-axis only — 50 Rejection/Text (49 with a quoted string) + 50 Discriminative/Text positives, own box vs GT box, ≈ 600 (candidate, clause) prompts ≈ 15 min GPU. If that fails, stop.

## Idea 3 — Transplanted presence head on frozen hidden states (SAM 3 style), trained on 2–3k mined hard negatives, evaluated as risk–coverage

**Mechanism targeted**: D1 + D3 as a *deployable channel*: a separate null decision beside the coordinate stream, so positives cannot collapse the way GroundingME's 2:1 SFT did (Disc 61.3 → 40.2) and SAM 3's Table 10 predicts (masking per-candidate loss on negatives beats DETR-style negative supervision) `[VERIFIED: 2511.16719 Table 10; 2512.17495 Table 7]`. Assumes Dispute A → sub-axis (negatives are mined per sub-axis and the head is scored per sub-axis); assumes Dispute B → negative type (the head never sees a format).

**Method.** Freeze Qwen3-VL-8B (or 4B). Features: the residual state at the best (layer, position) from Idea 1, or, without waiting for Idea 1, a fixed set {layer 18, 24, 30} × {last-expression token, mean-image, decision token} concatenated. Head: logistic regression → 2-layer MLP (d → 512 → 1) → one cross-attention query over the image tokens at one mid layer (a literal SAM-3 presence token, ≈ 4096² ≈ 17M params), in that order of capacity, each with 5-fold CV on the *training* pool only. Training pool: 2–3k items = arm-A N0 flips + arm-B N0' edits + C controls + P1 positives from the RL-design S1 (adversarially filtered: gate 1 keeps only negatives the base boxes), ratio ≈ 1:1, none from GME images (pHash exclusion, `schema.assert_dev_slice_disjoint`). BCE on presence; the coordinate stream is never touched. Inference: run the head on the same forward pass that produces the box; emit `null` iff head score < τ, τ set on a held-out slice of the training pool at 5 % false-null; report the full risk–coverage curve (AURC) on GME with `null` as abstention, plus the SAM 3 product rule (box kept iff head passes) as a second operating point.

**Closest prior work and delta.** SAM 3 presence token `[VERIFIED: 2511.16719]`: joint training, +1.5 cgF1 / +0.05 IL_MCC from the head, +0.24 IL_MCC from 30 hard negatives/image — the data term dominates. CLIP-UP `[LIKELY: 2501.01371 abs]`: a lightweight module on a frozen VLM for MM-UPD (structural unanswerables). Reliable VQA selector / HARMONY `[VERIFIED: 2204.13631 abs; 2510.22171]`: trained selectors on hidden states beat softmax 2× at 1 % risk; 0.87–0.89 AUROC on VizWiz. HKVLM `[VERIFIED: 2606.28862]`: existence verifier on a frozen detector + Qwen, weak base (RefCOCO+ 0.40). Delta: a presence head on a *frozen coordinate-emitting MLLM*, trained on adversarially filtered *attribute-false* negatives of the GME sub-axis types, scored by AURC on L4 with the positive cost bounded to false nulls by construction — Survey C's stated obstacle ("nobody has reported a presence-token MLLM on attribute-false negatives with the positive cost alongside").

**Kill experiment.** *Decides*: whether a few-thousand-sample supervised read-out can recover hard-negative rejection without touching the weights, and at what coverage. *Headline claim*: "a frozen-backbone presence head gives Rejection ≥ 25 at ≤ 5 % false-null and 0 parse failures, with every positive dimension unchanged by construction". *Precondition*: the RL-design S0 gates (data exists and is hard: gate 1 ≥ 90 % boxed, gate 2 ≥ 80 % listener-unique). *Instrument role*: the head's AURC is the operating-point baseline every weight-changing arm must beat at equal false-null; and the head trained on the *base* model can be re-applied to RL checkpoints to see whether training moved the representation the head reads. *Pre-registered stop rule*: with ≥ 2k training items, if the head's AUROC absent-vs-Discriminative-present on GME is < 0.70, or if at 5 % false-null on 804 it catches < 15 % of the 201 (below the CI floor), stop; report the S1 → S3 transfer curve as the negative result. *Cheaper decisive variant*: linear head on 500 arm-A N0 pairs only (≈ 1.5 GPU-h including S0 arm A): if GME AUROC < 0.60 at 500, do not build 3k.

## Idea 4 — Attention-on-region as a per-box score, with K sampled proposals and a calibrated max-score rejection rule

**Mechanism targeted**: D3 (no per-candidate score in the output channel) — does the model's own attention give the box a score, and is that score *absence-sensitive* or only *objectness/correctness*-sensitive? Assumes nothing about Dispute A (stratified); assumes Dispute B → negative type. Expected to **fail as a rejection score** and to **succeed as a correctness score**; both outcomes are used.

**Method.** Load with `attn_implementation="eager"`, `output_attentions=True`. Greedy decode; for the emitted coordinate and label tokens, take the attention from those decode positions onto the image tokens inside the emitted box (Propose-and-Attend's MTLA: heads averaged, layers 8–21 of 36 `[VERIFIED: 2607.05978]`; also sweep layer bands 4–12 / 12–24 / 24–36 since the paper's band was chosen on COCO detection). Score s = mean in-box attention mass (and the in-box / out-of-box ratio). Then K = 8 samples at T = 1 per item; each sample's box is scored; rejection rule: `null` iff max_k s_k < τ, τ set on the 333 base-correct positives' greedy scores at the 5th percentile (deployable) — not on the 201. Report three AUROCs: (i) absent (201) vs Discriminative-present (204), greedy; (ii) wrong-vs-right on the 763 boxed positives (the P&A replication on GME, which nobody has run on an unsaturated benchmark); (iii) max-over-K vs greedy for both. Also the free SafeGround-style dispersion (mean pairwise IoU across the K samples) as a fourth score `[VERIFIED: 2602.02419: 0.70–0.82 on GUI]`.

**Closest prior work and delta.** Propose-and-Attend `[VERIFIED: 2607.05978]`: MTLA 0.89 vs token log-prob 0.69 for "box matches no GT" on COCO with Qwen3-VL-8B — absence of the *expression's referent* never tested. SafeGround `[VERIFIED: 2602.02419]`: sampled-click dispersion, no absent targets. DIML / HaloProbe `[VERIFIED: 2411.16724; 2604.06165]`: image-attention ratio for hallucinated caption objects (0.74 / 0.935), category-level. Delta: first absence test of attention-on-region on L4 negatives, the K-proposal max-score rule with an off-GME threshold, and the correctness replication on GME stratified by dimension (feeds the positive-side program and IDEA-11 Stage 5).

**Kill experiment.** *Decides*: whether any attention-derived per-box score separates "boxed a same-class object that does not satisfy the description" from "boxed the right object". *Headline claim*: none expected; the paper-grade outcome would be AUROC (i) ≥ 0.75, which would contradict D2's reading (the box on a Rejection item is a confident same-class partial match, and attention will sit on it). *Instrument role*: score (ii) is the box-correctness instrument for the positives program (a training-free version of the confidence IDEA-11 Stage 5 needs); and a *negative* (i) with a positive (ii) is the cleanest evidence that objectness and description-satisfaction are different quantities inside the model — the D3 split. *Pre-registered stop rule*: (i) < 0.65 at every layer band → dead as a rejection channel, do not build the K-sample rule; (ii) < 0.70 → the P&A result does not carry to REC on hard positives either, and the whole attention-score family is dropped from Stage 5. *Cheaper decisive variant*: greedy only, 405 items, three layer bands: ≈ 0.4 GPU-h, answers (i) and half of (ii).

**Traps and controls.** *Visibility in disguise*: in-box mass scales with box area → report ρ(s, box area) and the area-normalised variant; AUROC absent vs Limited/Small must not be < 0.5. *Position confound*: HaloProbe found attention scores confounded by token position and repetition (Simpson's paradox) `[VERIFIED: 2604.06165]` — the coordinate tokens sit at fixed positions in the JSON, so compare per-token-position means. *Objectness in disguise*: the null hypothesis; test with a class-agnostic saliency peak inside the box (does s track saliency?) — the same null IDEA-11's census uses. *Oracle*: no best-of-K by GT; the max-score rule is the only selector, thresholded off-GME.

## Idea 5 — Two-sided load-bearing audit at inference: which clauses move the emitted box (text side), and is the emitted box load-bearing for the answer (image side)

**Mechanism targeted**: D2 as a *behavioural* claim about the policy ("clauses never enter the decision") rather than the p(null) reading; D3 (a per-item score from sensitivity); ties to IDEA-91's N+ (right box, wrong reason). Assumes Dispute A is answered by the audit itself (load-bearing fraction by sub-axis × length); assumes Dispute B → negative type (the box decision, not the format, is probed).

**Method.** *Text side* (no images edited): for each item, for each atomic clause c_i (decomposition from Idea 2): (a) DROP — re-ask with c_i deleted; (b) FLIP — re-ask with c_i replaced by a plausible different value (RL-DESIGN `expr_flip_clause.txt`, text-only LLM). Record whether the greedy box moves (IoU < 0.5 with the original box) and Δlog p(null). A clause is *load-bearing* if DROP or FLIP moves the box. Per item: load-bearing fraction f = #load-bearing / #clauses, and the *ignored-clause* count (neither DROP nor FLIP moves the box). Rejection rule (deployable): `null` iff f = 0, i.e. no clause beyond the head noun affects the box, with a matched rule on positives for false-null. *Image side* (IDEA-91's operators on the policy's own box): LaMa-inpaint the emitted box, re-ask; matched-size CONTROL inpaint elsewhere, re-ask; record Δlog p(null), whether the new box lands on another same-class object, and the K1 clean gate on a 50-item human sample. Statistic: absent-vs-Discriminative-present AUROC of f (text) and of Δ_REMOVE − Δ_CONTROL (image); and the mechanism table: f on the 333 base-correct positives (do clauses enter the decision when the model is right?) vs on the 338 wrong-object positives vs on the 201.

**Closest prior work and delta.** IDEA-91 `[P: team/ideas/IDEA-91]`: REMOVE/CONTROL on the GT referent to audit N+; here the intervention is on the *emitted* box and on *clauses*, unlabelled. RL-DESIGN gate 4 (load-bearing rate) `[P: notes/RL-DESIGN §1.4]`: measured with a cross-family *listener* to certify data; here measured on the *policy* as an inference-time signal and a mechanism metric. BCEA `[VERIFIED: 2606.16667]`: ℓ(x) − ℓ(∅) with masked variants for existence claims (0.86–0.88); EAZY `[VERIFIED: 2503.07772]`: zero the attended image tokens and see whether the object vanishes; KnowDR-REC `[VERIFIED: 2508.14080]`: Acc 64.6 matched vs 59.6 adversarially mismatched — "the box is chosen before the text is checked", the population-level version of the text-side audit. Counterfactual grounding uncertainty in clinical LVLMs `[LIKELY: 2606.28520 abs]`: positive vs counterfactual confidence + grounding overlap per entity — nearest image-side relative, medical, not REC. Delta: the first per-item, per-clause sensitivity audit of the emitted box on L4 negatives and matched positives, giving both a label-free rejection score and the direct behavioural test of "clauses do not enter the decision".

**Kill experiment.** *Decides*: two things at once — (1) whether clauses move the box on positives at all (if f ≈ 0 on the 333 correct positives, selection is head-noun-driven even when right, and any "verification" training must create the operation from nothing); (2) whether f separates negatives from positives. *Headline claim*: mechanism paper if f(correct positives) ≥ 0.4 and f(Rejection) ≤ 0.15 (clauses are used when the referent exists and ignored when it does not — the partial-match acceptance made visible). *Instrument role*: f is the **"clauses enter the decision" metric** for every training checkpoint — the policy-side twin of the RL-design's meta-generalisation test; a checkpoint whose Rejection rises while f on positives stays flat learned a switch. *Pre-registered stop rule*: as a rejection score, stop if AUROC(f) < 0.60 absent-vs-Discriminative-present; the mechanism result is reported regardless. Image side stops if Δ_REMOVE − Δ_CONTROL AUROC < 0.60 or the K1 clean rate on emitted boxes < 0.50 (object-sized boxes, median 5 % of the image `[P: diagnosis §3]`, may not inpaint cleanly). *Cheaper decisive variant*: text side, DROP only, 405 items × 6 clauses ≈ 2.4k passes ≈ 1 GPU-h; no LLM flips, no editor.

**Cost table.**

|---|---|---|---|---|---|---|

| DROP + FLIP re-asks | 405 × 6 × 2 ≈ 4.9k generate calls (64 tokens) | 8B-Instruct | ~22 GB | ~18 GB | 2.0 (1.4 s each) | local |

Total ≈ 3–5 GPU-h local.

**Predicted outcome** `[SPECULATION]`: f on correct positives 0.35–0.50 (Discriminative higher, Limited lower — short expressions); f on wrong-object positives 0.15–0.25; f on Rejection 0.15–0.25 (the same population as wrong-object, per diagnosis §7); AUROC(f) 0.62–0.70; by sub-axis, Text clauses load-bearing far more often than Appearance/State (the FLIP of a quoted string moves the box; the FLIP of "worn-looking" does not). Image side: Δ_REMOVE − Δ_CONTROL AUROC 0.55–0.62 (the model re-boxes a substitute on both populations, as 94.3 % of REMOVE boxes already do `[P: diagnosis §6]`). *What kills it*: f ≈ 0.1 everywhere (the head-noun-only reading is total; no rejection signal, but a decisive mechanism result); or f high on Rejection too (clauses are used and the false clause is *accepted* — verification, not integration, is the failure, which hands the problem to Idea 2's isolation test).

**Guardrails.** False-null of the f = 0 rule on 804 by dimension (Limited's 1–2-clause expressions will hit f = 0 often — report the rule only on items with ≥ 3 clauses, and say so); FLIP plausibility spot-check (50 by hand: an absurd flip that moves the box is not evidence of clause use); parse failures on re-asks counted separately; box-move threshold reported at IoU 0.5 and 0.3.

**Traps and controls.** *Length as a confound*: f is a fraction, but the number of clauses differs by dimension — report f and the raw load-bearing count, stratified by clause count. *Sentence oddity*: DROP can leave an ungrammatical remainder that moves the box for the wrong reason — the FLIP arm controls this (grammatical, one value changed); report both and their agreement. *Multi-instance positives*: on Discriminative items with several GT-equivalent instances the box may legitimately move to another satisfier — treat "moved onto another GT instance" as not-moved (IDEA-11 11-M4 set-aware rule). *Artifact on the image side*: the CONTROL edit is mandatory; the clean rate is measured on emitted boxes specifically. *Prefill*: because errors are committed in prefill `[VERIFIED: 2605.12549]`, a clause that moves the box does so by changing prefill — the audit is therefore a prefill sensitivity map, and the text-side numbers can be cross-checked against Idea 1's probe at the clause-end positions for free.

## Idea 7 — Prompt-level scaffolds measured honestly: explicit null instruction, in-context null demonstration, list-then-verify in one call, deliberate-then-decide in two calls

**Mechanism targeted**: Dispute B directly (format vs negative type): how many points a prompt can buy on L4, at what false-null; D8 (does a demonstration of `null` unlock the output prior); D2 (does an enumerate-then-check scaffold in the prompt change the box decision). Assumes nothing about Dispute A (stratified). Cheap, probably mostly format — and the floor every other idea and every training arm must beat.

**Method.** Five variants on all 1,005 (decision token read + free generation): (a) the harness prompt (baseline, byte-identical to GroundingME); (b) + one sentence: "Output `{"bbox_2d": null}` if any part of the description is not satisfied by any object; a partial match is not a match"; (c) + a one-shot in-context demonstration (a second image + a description with one false clause + the null answer; the demo image from the pilot set, never GME); (d) list-then-verify in one call: "First list every <head noun> in the image and for each state which parts of the description it satisfies; then output the JSON" — the model's own candidates, single pass; (e) deliberate-then-decide in two calls (MEGA-GUI): call 1 asks for the per-candidate check as free text; call 2 receives the image, the description and call 1's text and outputs only the JSON. Report per variant: literal-null on 201, parse-failure, false-null on 804 by dimension × size, Acc@0.5 on the 804 (a scaffold that costs Discriminative is not free), and p(null) AUROC at the decision token (does the prompt move the *representation at the decision token* or only the output?).

**Closest prior work and delta.** MM-UPD `[VERIFIED: 2403.20331]`: option / instruction settings move UPD by tens of points (structural unanswerables). Diagnostician probe 5 `[P: diagnosis §8]`: proposed but uncosted; SurveyB §5: "`{"bbox_2d": null}` *is* that option and is in the prompt; 0/201 — the prompt lever is already pulled" — this idea tests whether the *demonstration* and *scaffold* levers are also pulled. **Kill experiment.** *Decides*: the size of the format term on GME. *Headline claim*: none (instrument / baseline). *Pre-registered stop rule*: if no variant reaches literal-null ≥ 10 % on the 201 at ≤ 5 % false-null, prompting is exhausted and Dispute B resolves to negative type for GME; any variant that does reach it becomes the mandatory baseline row in every training table. If (b) or (c) alone moves Rejection ≥ 10, a format term exists and every published 0.0 is partly a prompt effect — report to SurveyD. *Cheaper decisive variant*: (b) and (e) on 201 + 204 only ≈ 0.6 GPU-h.
