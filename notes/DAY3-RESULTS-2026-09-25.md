# 第三天结果：裁剪路线与当前最佳配置（2026-09-26 晨）

承接 `NIGHT2-RESULTS-2026-09-25.md`。全部本地 4B，无 API 调用；RefCOCO train 标注与 600 张 COCO 图经你批准下载。V3e（加长 RL）仍在跑，见文末。

## 一句话

自提示裁剪把方法从"感知封顶"里解出来了。V3d 在 GME **全集**（1,005 条）拒答 32.3、正样本 38.3（基座 39.8）、灰图差 3 点，RefCOCO 90/80/87（基座 90/84/87）；同配方多训一轮的 V3e 在开发集拒答 **40.3**、正样本 42.0（基座 39.8）、RefCOCO 90/83/86，达到这一阶段定的目标线（拒答 ≥ 40、正样本不低于基座、RefCOCO 在 3 分内），全集与灰图正在跑。GME 自家 SFT 是 27.9 换 Discriminative −21。瓶颈从"看不清"转到了"基座给的提示框只在 45% 的正样本上命中"。

## 现在的端到端方法

一个模型，两次前向。第一次：基座权重（关掉 LoRA）用 GME 原 prompt 给一个框，作为提示。第二次：同一模型的 LoRA 用核对轨迹 prompt，输入全图加提示框的原分辨率裁剪，输出条件列表、候选表（提示对象排第一，逐条 yes/no）、答案；评测取由表推导的答案。

训练：SFT 用标签渲染的轨迹（先承诺顺序；训练时的提示框直接取 datagen 记录的基座框，与推理分布一致；50% 的样本做尺度增强，把物体缩到 GME 的占比）。GRPO：对级奖励（负样本 null 的分数 = 同图正样本的答对率）、对推导答案计分、承诺奖励（第一候选与目标的 IoU × 0.5）、正样本答 null 扣 1、负样本无 null 时注入标签轨迹、混入 100 条 RefCOCO train 只用答案奖励。

## 为什么裁剪起作用，为什么提示是新瓶颈

- 分辨率测试（H5）：物体缩到 GME 尺度后，全局视图核对的真子句误判从 13% 升到 31%，裁剪保持 14%。裁剪 SFT 把拒答从 25.9 提到 36.8，同时正样本 +5、RefCOCO +5。
- 提示决定正样本：V3d 在提示框正确的 67 个正样本里答对 65 个；提示框错的 83 个里答对 1 个。基座直接定位在 GME 正样本上的命中率就是 45%，这是 GME 已知的"选错物体"问题。
- 三个试图修提示的办法都没用：提示阶段像素翻倍（命中 67 → 68）；30% 错提示的 SFT（错提示下答对 2/83）；三张裁剪（3/84，评测成本两到三倍）。原因一致：基座在直接框错时，它列出的候选里也基本没有目标，问题在候选生成端。
- RL 的作用：一轮（V3d）把误拒从 44 压到 21、正样本从 38 拉到 44，代价是拒答 36.8 → 32.3，去掉的主要是"提示错、顺手答 null"的幸运拒答；两轮（V3e）拒答回到 40.3（配对 +8.0），正样本 42.0（−2.0），误拒 31，推理与答案一致率 89%。RL 的长度决定交换点的位置，是配方的一部分，需要多个种子确认（第二个种子在跑）。

## 其他学到的

- 数据扩容（330 条备选改假句、170 条矩阵唯一的短表达式）在 GME 上中性，短表达式给 RefCOCO +1.7；RefCOCO train 混进 RL 让 RefCOCO 和 RefCOCOg 回到基座。
- 三种奖励（独立、对级、门控）在 60 步单种子下差别在噪声内；对级奖励是唯一把正样本拉回基座的，之后一直沿用。
- 孤立核对探针：基座 4B 对 GME 上 V3b 的承诺候选逐条核对，硬规则拒答 83% 但正样本 70% 被否；软阈值的 AUROC 只有 0.58 到 0.77。校准解决不了它，感知视角（裁剪）才解决。
- 成本：裁剪 SFT 约 17 分钟，裁剪评测约 45 分钟，裁剪 GRPO 约 105 分钟一轮，三裁剪评测 4.6 小时。

## 建议下一步

1. **提示质量是杠杆**。三个方向：用训好的模型自己的第一候选替代基座提示并迭代一次；用基座的多目标检测（"找出全部 X"）生成候选再裁剪，需要先抽中心名词；或在提示阶段换更大的基座（8B）做级联，代价是多一个模型。
2. **加长 RL**（V3e 在跑）与 3 个种子，确认 V3d 不是偶然。
3. 冻结配方后做迁移评测（POPE、空间关系）与 FineCops-Ref、gRefCOCO 的同基座对比，这是 scope 里的通用性主张。
4. 扩数据到一两千场景时，按每场景实例数分层，专门补"目标小、同类多"的场景。
