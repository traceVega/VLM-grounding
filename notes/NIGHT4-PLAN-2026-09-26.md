## Finding at 01:20: row-1 confirmation bias (`train/_rowpos.py`)

On `scr_sft_v2_b400` positives the derived answer is row 1 in 60 of 67 box answers; of 23 wrong picks with the object among the candidates, 22 chose row 1; the object sits in row 1 only 32/70 times. The commit-first SFT labels (described object always row 1) taught "row 1 fits": the table confirms the top proposal instead of discriminating. The half-scene SFT shows the same (19/21). Also the object's own row carries a false "no" in 24/70 cases.
→ Added `--order random` (rows shuffled per rendering; CPU check: label-consistent 29/29, object in row 1 only 3/17) and queued **sft_v2h_rand** (half scenes, shuffled rows) + screening after probe A; the v2b handoff picks the RL base by screening (net rejection + 0.5·positive acc) between `sft_v2_half` and `sft_v2h_rand`.
Isolated probe A cannot remove this prior (every isolated candidate is "row 1"), so it mainly tests copy-paste.

## Probe A result (02:08): isolated per-candidate verification is not a win

`scr_sft_v2_iso` (same turn 1, each candidate verified alone): rejection 29.0 (joint 32.0), positives 33.3 (34.3), positive null 23.2 (31.3), net 5.8 (0.7); paired rejection only-iso 2 vs only-joint 5. Isolation lowers over-refusal a little but also rejection; within noise. Copy-paste across rows is not the mechanism; the row-1 prior and verdict leniency are. Dropped (the isolated eval also costs ~5× turn-2 calls).

## 03:50–04:30: shuffled rows lose; decision rules cannot move the trade-off; marked overview queued

- `scr_sft_v2h_rand` (half scenes, shuffled label rows): rejection 49.0 / positives 19.2 / positive null 52.5 / net −3.5 (commit-first half: 33.0 / 28.3 / 32.3 / 0.7). The row-1 prior is gone (wrong picks on row 1: 6/16) but the object's own row now carries a false "no" in 40/67 cases (24/70 before): without the positional prior the cell noise turns into nulls. v2b therefore started (03:51) from `sft_v2_half`, `--order random` only for the injected traces.
- Offline re-scoring (`train/_rules.py`) of the saved tables under other table→answer rules: excluding only with ≥2 "no" drops rejection to 6–8 (rejection items carry exactly one falsified clause); requiring a unique best raises positive nulls to 55–60. The current rule is the right point on the line; the line itself is set by per-cell verdict accuracy (false "no" on true clauses ≈ 17% per cell).
- Queued in v2c first: **sft_v2_ov** = turn 2 also receives the full image with the candidate boxes drawn and numbered (`VLMG_OVERVIEW=1`, `traces.mark_overview`), targeting Spatial (11%) and candidate identity; then RL-only, then the Gemini-rationale SFT. `sft_v2_rand` dropped.

## 09:20: grpo_v2 (RL from sft_v2_half) drifts to acceptance

`scr_grpo_v2`: rejection 16.0 / positives 33.3 / positive null 16.2 / net −0.2 (base SFT 33.0 / 28.3 / 32.3 / 0.7); own negatives 0.80 → 0.60, own positives 0.64 → 0.79; RefCOCO 78/74/90; Spatial 16 → 24. Training: neg_null 0.65 → 0.46, pos_null 0.14 → 0.04, completion length 437 → 382; the in-training mini-GME caught it (rejection 0.15 at step 40 → 0.05 at step 58, positive null flat 0.37). Row-1 confirmation is back at 80/83. Mechanism: a positive null costs −1 (plus the forgone box reward) while a correct null earns only the pair credit s⁺ ≤ 1, and positives outnumber negatives 2:1, so writing "no" is net-punished; the policy moves along the same trade-off line toward acceptance. v2c re-planned in place: `grpo_v2_sym` (same base, `--r-pos-null 0`, more negatives) → RL-only with the symmetric reward → Gemini SFT.

## 12:40–13:30: design panel, two bugs, the v3 combos

- Design panel (5 designers, 20 proposals, 2 judges): commit-first is defensible only for the turn-1 ordering, not as the table label; "no 'no' in 8 rollouts" is a support-set problem (SFT/data), the reward must not erase the support; the simplest reward (format + derived outcome) is right as a control with symmetric null, ~1:1 pairing, discrete outcome and no std normalisation (201/202 grpo_v2 groups had fake variance from soft-IoU/commit/stray terms); the multi-term reward was over-engineered (commit inert 32/70→32/70, reason inert .47→.50). Named-no derivation rule verified offline on six saved screenings (net +3.8 to +11.8, positive null −10 to −18, rejection −2 to −8): keep it as an inference/eval rule, not in labels or reward (would erase the bare/named signature). Column-wise verification rejected. Gemini-rationale SFT ablation cancelled (stopped 12:43), rationales folded into the combo.
- Bug 1: the three v2d RL arms (sym, cell, zero) crashed at step 1 (log writer summed None for the cell metric) — 0 GPU hours of RL ran; fixed.
- Bug 2: `render_table` re-ran `ordered_rows`, so under `--order random` the tool-call boxes and the table rows were shuffled independently: the "shuffled rows lose" run (`sft_v2h_rand`) trained on crops in one order and rows in another. That conclusion is unreliable. Orders are now seeded per scene (twins share, boxes == rows; 83/85 twins identical, 110/110 box/row agreement).
- v3 combos (queue `train/queues/v3.txt`, started 13:3x): **sft_v3** = half scenes, coin order (target first p=0.5 else a distractor first), verdict-token loss weights 4/2/0.5, marked overview, Gemini rationales → screening vs `scr_sft_v2_half_b400`; **grpo_v3** = from sft_v3, minimal discrete symmetric reward (format + derived outcome, positive null 0, negative null max(s⁺, 0.5), no commit/recall/reason/stray/soft-IoU, no std, siblings dropped for ~1:1, injection both ways) after a 2-scene smoke → screening vs `scr_grpo_v2`. Both screenings also re-scored under the named-no rule.
