# 设计：证据门控的拒答式视觉定位（Evidence-Gated Verified Grounding）

2026-09-24。主线采用用户提出的单轮结构化思维链（拆条件 → 逐候选核对 → 结论 → 答案），SFT 装格式，RL 磨命中率。本文给完整设计，并单列创新点与其充分性判断。前置文档：`reports/视觉定位 思维链 工具 训练机制.md`（文献）、`notes/POC-TRAIN-RESULTS-2026-09-24.md`（昨夜实测）、`notes/MECHANISM-DESIGN-2026-09-24.md`（被取代的两版）。

## 1. 问题与核心判断

任务：长描述（4–7 个细节）指向图中一个物体，图里有多个同类候选；描述若有一个细节为假，应答 null。目标：GroundingME 拒答显著提升，其余维度（GME 三类正样本、RefCOCO 系列、自家验证）不降。

昨夜的实测把失败机制钉死了：在坐标流里训 null，四种配方全部落在"拒答率 ≈ 误拒率"的一条线上，GME 上 p(null) 对拒答项 vs 正样本的 AUROC 0.33–0.39（低于随机）。null 学到的是"题目难"，不是"描述不满足"。原因有两层：决策没有证据约束（一瞥之下的一个 token），以及改假的细节在全局分辨率下常常看不见。

核心判断：**把拒答从"预测一个 token"改成"从逐条核对的证据里推出来的结论"，并且只在证据正确时给拒答奖励。** 格式让核对进入输出，标签让每一行核对都有真值，奖励让"没找到假细节就拒答"无利可图。

## 2. 方法

### 2.1 输出格式（单轮，一个模型，一个 prompt）

```
<think>
<conditions>1. 黑色车身 2. 车顶有行李架 3. 在红色车后方</conditions>
<candidates>
<object id="1" bbox="[x1,y1,x2,y2]">1: yes  2: yes  3: no (在红车侧方)  → 排除</object>
<object id="2" bbox="[x1,y1,x2,y2]">1: yes  2: yes  3: yes  → 满足</object>
<object id="3" bbox="[x1,y1,x2,y2]">1: no (银色)  2: unclear  3: yes  → 排除</object>
</candidates>
<verdict>唯一满足全部条件：object 2</verdict>      ← 或 "没有候选满足全部条件"
</think>
<answer>{"bbox_2d": [x1,y1,x2,y2]}</answer>              ← 或 {"bbox_2d": null}
```

规则：条件数 = 描述拆出的原子子句数；每个候选对每条给 yes / no / unclear，可附一个短括注；候选由模型自己列出（Qwen3-VL-4B 有多目标检测能力，召回不够时把检测器候选放进 prompt，即 Rex-Thinker 的 hint 形式）；答案只能是"唯一满足"的候选框，或 null。评测时只取 `<answer>`，与 GroundingME 协议一致。

思维链刻意短而结构化：文献里自由思维链在感知型 grounding 上每个尺寸都是负分，长链会让注意力离开视觉 token。

后手（不在主线）：若 §5 的分辩率测试表明模型在 GME 尺度下看不见细节，在同一格式里加一个 `<zoom id="k"/>` 动作，harness 把该候选按原图分辨率裁下附回，模型继续核对。Qwen3-VL 原生支持这个两轮协议。

### 2.2 数据引擎：从标签算轨迹，不请教师写

现有 datagen 已产出每个场景的：候选框（Molmo2 指点，人工审过的子集）、目标描述与兄弟描述的原子子句（写手 + 拆句）、被改假的那条子句、**每个候选 × 每条子句的 yes/no/unclear**（Gemini 批量核对 + 人工修正）、以及最终答案。一条轨迹就是把这张"候选 × 子句"矩阵按 §2.1 的格式渲染出来，结论和答案由矩阵决定。

每个场景出四条轨迹：目标描述（答目标框）、兄弟描述（答兄弟框）、改假描述（答 null）、跨场景描述（同一句话放到另一张同类图上，答 null）。同一句话在不同图上答案不同，纯文本记不住答案。现有约 800 条；用同一条链扩到 1–2k 场景可得 5–8k 条，Gemini 核对成本约 35 美元/千场景。

与业界轨迹的差别：Rex-Thinker 的 9 万条是 GPT-4o 看着标出的目标写的（教师不看答案只有 53 分，学生 82 分，学到的是格式）；ViGoRL 用 72B 做 MCTS 搜索。我们的每一行核对都对应一个经过核对的事实，轨迹与答案无关，且自带过程标签供 RL 使用。

### 2.3 SFT：装协议

标准做法：整条 `<think>` 加 `<answer>` 的下一个 token 交叉熵，prompt 部分不算 loss；LoRA r16，2–3 轮。混入 20% 只有 1–2 条条件的短描述（用兄弟描述截短生成），保住 RefCOCO 那类短句的行为。SFT 的验收只看两件事：格式是否稳定产出；自家验证上负样本 null 上升、正样本误拒不动。

### 2.4 RL：GRPO，五项奖励

| 项 | 定义 | 目的 |
|---|---|---|
| 答案 | 正样本：框 IoU≥0.5 得 1，错框 0，答 null −1；负样本：答 null 得 1（受下一行门控），给框 0；不可解析 −1 | 主目标；−1 是防过度拒答的主闸（RC-GRPO） |
| **证据门控** | 负样本的 null 只有在轨迹里把被改假的那条子句对至少一个候选标为 no 时才得 1，否则只得 0.2 | 让"不找假细节就拒答"无利可图；拒答成为结论而非先验 |
| 候选框 | 轨迹里的候选框与场景实例框做 IoU≥0.5 匹配，算 F1（召回 + 精度） | 精度项防枚举刷分（TreeVGR 教训），召回项防漏掉目标 |
| 一致性 | 答案必须等于 verdict 的结论（唯一满足者的框，或无满足者时 null），违反 −0.5 | 防"答案不跟着推理走"（Faithful GRPO：标准 GRPO 让不一致率 7% → 26%） |
| 过程 | 有标签的题上，核对表与标签矩阵的一致率 × 0.3 | 标签是策略没有的信息（PRM 只在评判者知道得更多时有用） |

格式奖励 0.1。防 hack 的固定约束：候选数上限 8，每候选判决数 = 条件数，无任何无条件加分，IoU 阈值可在后期从 0.5 收到 0.7（Vision-R1）。RL 数据只用 SFT 后解出率在 (0, 1) 的题；负样本若采不出 null 再启用强制注入（昨夜验证过 15 步即解锁）。LoRA、每题 8 条采样、无 KL 或极小 KL。RL 的预期贡献是在 SFT 之上加几分并提高域外泛化，不指望它创造能力。

### 2.5 护栏与对照（每次评测同报）

- 正样本误拒计数（不是率）、按物体尺寸分层；RefCOCO 短句作金丝雀。
- 灰图对照：拒答项与正样本在灰图上的 null 率之差应接近 0（基座两者都 ≈98%）。
- 文本地板：纯文本判官在同批负样本上的 AUROC（GME 是 0.92），任何增益必须高于它。
- 忠实性：答案与 verdict 一致率；核对表在自家验证上的逐子句准确率。

## 3. 评测与消融

主评测 GroundingME 全集 1,005（拒答 201 按官方规则、三类正样本按维度、误拒计数），自家验证 48，RefCOCO/+/g 各 300，灰图。开发期用固定子集配对比较，全集只给最终候选。

消融（同种子同数据）：基座；坐标流 SFT / RC-GRPO（已有）；格式 SFT；格式 SFT + 仅答案奖励的 GRPO；+ 证据门控；+ 候选 F1；+ 过程奖励；用 Gemini 看着答案写的轨迹替代标签轨迹（检验"轨迹从标签算"是否真的重要）；zoom 变体（若启用）。这张表就是论文的主表。

## 4. 创新点与充分性

先说不是创新的部分：格式是 Rex-Thinker 的；GRPO、不对称惩罚、一致性奖励、候选 F1 各有出处。这些是"用了领域的标准件"。

独到之处有三条，按重要性排：

1. **证据门控的拒答奖励**。所有已有方法（RC-GRPO、ViSurf、GroundingME 自己的 SFT）对 null 的奖励是无条件的，所以模型学会"不确定就拒"，拒答率和误拒率同步上升，这正是我们在四种配方上量到的那条线。我们的 null 只有在轨迹正确指出被改假的细节时才得分。据调研，没有方法这样做过；RC-GRPO 第二阶段的"说出错在哪句"是加分项不是门控，只带来 +1.6。这一条直接针对我们量出的失败机制。
2. **从子句级标签算出的验证轨迹**。领域里的思维链数据要么是强模型看着答案写的（Rex-Thinker、DeepEyesV2），要么是 MCTS 搜的（ViGoRL）。我们的数据引擎本身就产出"候选 × 子句"的核对矩阵，轨迹是它的确定性渲染：每一行都是核对过的事实，轨迹与答案无关，过程标签免费。同时它是第一个针对 GroundingME 那类负样本（人写长描述里改假一个从句、类别在场）的训练数据引擎，GroundingME 没有训练集也没公开其负样本构造。
3. **实证与对照**。昨夜的结果（四配方一条线、AUROC 低于随机、null 按难度触发）是一个清楚的负结果和机制解释；若新方法把 GME 拒答从 0 推到几十分而正样本不掉，就是第一个离开这条线的方法。加上灰图和文本地板对照，这是领域里罕见的完整性（20 个已有方案里 9 个没有灰图对照）。

充分性判断，直说：作为 PoC 和技术报告，足够。作为主会论文，格式本身不是卖点，审稿人会说"Rex-Thinker 加 RC-GRPO 换了个 benchmark"；能挡住这句话的是第 1 条和第 2 条，以及主表里"仅答案奖励 vs 加证据门控"那一行的差距。如果门控带来的只是一两分，创新性就撑不住，论文只剩分析价值；如果它是把拒答和误拒解耦的那一项，故事就成立。所以消融表里那一行必须做，而且要做干净。若后手 zoom 被启用，"在核对链里放大候选再判"是调研确认的空白（没有论文把裁剪工具和拒答放在一起），会成为第四条。

不打算主张的：新 RL 算法、新架构、新 benchmark。

## 5. 主要风险与对应

- **看不见细节**（最大风险）：把自家场景缩放到 GME 的物体尺度再测核对准确率，几十分钟能出结果；不行就启用 `<zoom>`。
- **候选召回**：模型列不全同类物体则目标缺席。零样本先量召回；不够就用检测器候选进 prompt（Rex-Thinker 的做法，它的 hint 一项值 +11.8）。
- **过度拒答换形式回来**：门控让盲拒无利，但模型可能学会"随便挑一条标 no"。过程奖励对标签、候选 F1、以及负样本里"其他子句为真"的标签会惩罚它；误拒计数每次报。
- **文本捷径**：GME 负样本纯文本可分性 0.92。跨场景同文本对、灰图对照、文本地板三层控制；核对是按候选给出的，文本本身给不出答案。
- **拆句质量**：GME 是人写的 54 词段落；抽 50 条人工看拆句。
- **数据量**：800 条能装格式，核对能力需要更多标签；扩到 1–2k 场景是第二步，不是前提。

## 6. 执行顺序（不开始，仅列出）

1. 三个测试：分辩率缩放测试；4B 候选召回；轨迹渲染检查（抽 30 条人读）。
2. 格式 SFT，看自家验证与 GME 开发子集。
3. GRPO：先只有答案奖励，再逐项加门控、候选 F1、过程奖励，各记一行。
4. 通过后扩数据到 1–2k 场景，跑全集与全部对照。
5. 视 1 的结果决定是否启用 zoom。
