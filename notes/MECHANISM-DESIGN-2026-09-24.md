# 训练机制设计：先核对基座自己的框，再逐候选重选（2026-09-24）

调研报告：`reports/视觉定位 思维链 工具 训练机制.md`（四份文献切片 + 本项目证据，含机制对比表 M1–M9 和 kill 实验 K1–K6）。本文是我在报告之上的决定：**做什么、按什么顺序、每一步的 loss 和判据**，以及与报告不同的两处取舍。

## 0. 决定（一段话）

不再在坐标流里教模型输出 null，也不做自由思维链或让策略自己决定要不要裁剪。机制是**"先答后核对"**：基座权重照常给框；把它框住的物体按原图分辨率裁下来，配上描述拆出的每条子句，让一个训过的 4B 核对 LoRA 逐条判 yes/no/unclear；由校准过的规则从这些判决算出"否决为 null"还是"保留框"。第二阶段再列出同类候选、逐候选核对、按得分重选，这一步才是正样本（选错物体的 338/804）的提升来源。文献两类机制各借一半：Rex-Thinker 的"答案是逐候选判决的函数"，和 zoom 工具线的"裁剪进上下文"，但裁剪由代码强制执行、判决由核对算出，不由策略自选、不由坐标流预测。

## 1. 为什么是它（四条本项目实测 + 两条文献结论）

| 证据 | 含义 |
|---|---|
| 四种配方（SFT、SFT+跨场景负样本+UL、RC-GRPO、ViSurf 式 GRPO）在 GME 上"拒答率 ≈ 误拒率"，p(null) AUROC 0.33–0.39 | 坐标流里的 null 学的是难度，不是"描述是否满足"；调损失/奖励只在一条线上滑 |
| verify-first 提示（全图、整段、单次调用）在 4B/8B 零样本都不区分（0.109 vs 0.153；0.144 vs 0.147），模型把假细节标 true | 全局分辨率下看不见被改假的细节；格式激活不了看不见的东西 |
| 裁剪 + 单条子句 + 独立调用：8B 对改假子句判 no 0.914（Gemini 0.929、Gemma-4 0.914），真子句误 no 0.18 | 核对能力**存在**，条件是"看得更少、像素更多、一次一句"；剩下的是校准问题 |
| 基座在灰图上对拒答项和正样本都 97–98% null | 灰图对照要读"拒答项与正样本 null 率之差" |
| 文献：思维链在感知型 grounding 上每个尺寸都为负（Qwen3-VL-4B Thinking RefCOCO −0.8、ODinW −8.8；GME 8B Disc 61.3→52.5）；工具 RL 在 ≤7B 无 REC/拒答结果，纯结果奖励会淘汰工具，工具只贡献增益的 22–30% | 两类机制都不能直接作主线 |
| 文献：presence 放在坐标流外是唯一"对正样本免费"的家族（SAM 3 presence token pmF1 −2；GSVA 去 [REJ] N-acc 56→30）；核对者只有在"比策略知道得多"时才有用 | 判决必须由另一个信息源算出来 |

## 2. 机制（按阶段，每阶段一个可部署的系统）

### 阶段 1：核对基座自己的框（veto-only，只有一个候选）

推理流程（每题 2 次模型调用 + 1 次本地拆句）：

1. 基座权重、GME 原 prompt → 框 b（或它本来就给的 null，照旧）。
2. 本地 Qwen3.5-9B 把描述拆成原子子句 c₁…cₙ，并抽出中心名词（datagen 的 decompose 阶段，GME 文本不出本机）。
3. 核对 LoRA：输入 [全图，b 画红框] + [b 的原图分辨率裁剪] + "The outlined {类别}: 1. c₁ 2. c₂ …"，输出每行 yes/no/unclear，同时读判决 token 的概率。
4. 规则：s = Σᵢ log p(yesᵢ) 只对判为 yes/no 的子句累加，unclear 不计；若 s < θ 输出 `{"bbox_2d": null}`，否则保留 b。θ 在自家留出正样本上按误拒预算定（基座框对的正样本误否决 ≤3%，小物体层 ≤5%）。

为什么第一阶段不列候选：拒答项里基座无论框了谁，那个物体至少有一条子句为假，所以只核对基座的框就能抓到拒答；正样本只在"基座框对且核对者误判"时受损，这个量可测可控；不需要候选枚举、不受召回率限制；GME 上基座的框已经缓存（`~/vlmg-data/train/eval/base4b/gme.jsonl`），核对结果也可缓存，阈值和聚合规则离线扫，一轮迭代从 20 分钟变成几秒。

### 阶段 2：列候选 + 重选（正样本的提升来源）

1. 基座列出中心名词类别的全部实例框（零样本先量召回；不够就用 SAM 3 作提议器）；基座自己的框永远是候选 0。
2. 每个候选各核对一次（同上），得到候选 × 子句的概率矩阵。
3. 规则：每个候选得分 sⱼ；max sⱼ < θ → null；否则输出 argmax 的框，但只有当它比候选 0 高出 δ 才换（δ 在留出集上定，防止改坏基座本来对的）。

### 阶段 3（可选）：折叠成一个模型的两轮模板

第一轮：基座式输出候选框；harness 裁剪并把裁剪附进第二轮；第二轮：输出核对表 + 最后一行 JSON。训练轨迹全部由阶段 2 的管线从像素算出，不是看着答案写的；裁剪由 harness 强制，策略不选择"要不要裁"。SFT 只在核对表和答案 token 上算 loss；再 GRPO：答案奖励 + 0.3 × 核对表与标签一致（带精度项）− 答案与核对表不一致罚。这是把用户说的两类机制用诚实的方式合起来的形态，但它有注意力稀释的风险（K 张裁剪同时进上下文），所以只在阶段 1–2 通过后做，管线版是它的上界。

## 3. 训练：只训核对者，loss 是校准问题

| 项 | 做法 |
|---|---|
| 样本 | 一个（场景，候选）= 一条样本：[红框全图] + [裁剪] + 子句列表 → "1: yes\n2: no\n…"。现有 205 场景 ≈ 800 条样本、4–5k 子句标签（Gemini 判定 + 人工修正场景覆盖；8B 与 4B 同源，只作参考不作标签） |
| loss | 只在 yes/no/unclear 三个词的位置算交叉熵（序号、冒号 mask 掉）。真子句被判 no 的位置权重 ×2–3（过度拒答是约束方）。unclear 保留为第三类，不 mask |
| 抗捷径 | 同一句子在目标裁剪上 yes、在兄弟裁剪上 no（候选矩阵天然如此）；灰裁剪（图换灰、句不变）标 unclear 混入；可选：同一子句、目标裁剪 vs 兄弟裁剪的成对损失 |
| 校准 | 训后在留出场景上温度校准，报 ECE；阈值 θ 只按误拒预算定 |
| 通过判据 | 留出子句 AUROC ≥0.90；真句误 no 18% → ≤8%；灰裁剪 AUROC ≤0.60；改假子句判 no ≥0.90 |
| 规模 | 先用现有 4–5k 标签；不够再用 datagen 链扩到 1–2k 场景（Gemini 合并核对约 35 美元/千场景），每子轴人工各 100 条金标 |
| RL | 不用于 null 决策（采不出、且已证只沿线滑）。只留两处：候选枚举（集合 F1 对 SAM 3 真值）和阶段 3 的一致性奖励 |

## 4. Kill 实验（按信息成本；GME 只在本地）

| # | 实验 | 数据 / 模型 | GPU-h | 预注册判据 | 杀什么 |
|---|---|---|---|---|---|
| K1 | 4B 零样本作"裁剪 + 子句"核对者；同报 yes/no 形式与"问值不告"形式；灰裁剪对照 | 现有 4–5k 标签，人工场景为金标 | 0.3 | 改假子句判 no ≥0.85；真句误 no ≤20%；灰裁剪 AUROC ≤0.60 | <0.70 → 4B 在裁剪上也核对不了，核对者换 8B（推理可共驻）或换路 |
| **K2** | **阶段 1 零样本上 GME**：缓存的基座框 → 拆句 → 核对 → 离线扫 θ | 1,005 条 GME + 同批灰图；4B（8B 对照） | 0.5 + 0.5 | 条目级 AUROC（拒答项 vs 基座框对的正样本）≥0.80，灰图 ≤0.60；**误否决 3% 处拒答召回 ≥30%**；Text 子轴 ≥0.85 | AUROC <0.65 → 裁剪也救不了 GME 分辨率下的细节，核对家族在 GME 上死 |
| K3 | 训核对 LoRA，重跑 K1/K2 | 同上 | 1 + 0.5 | §3 判据；K2 曲线整体上移 | 无改善 → 先清标签噪声（双核对者分歧 19%）再扩数据 |
| K4 | 阶段 1 端到端全量评测 | GME 1,005、GME 灰图、自家 48、RefCOCO 各 300 | 2 | 拒答 ≥25（n=201，CI ±6）；804 正样本 ≥ 基线 −1；RefCOCO ≥ 基线 −1；灰图两率之差 ≈0 | 正样本掉 → 收紧 θ；拒答不够 → 上限在 K2 已知，扩标签 |
| K5 | 候选枚举召回 + 阶段 2 重选 | 自家 500 场景（SAM 3 真值）+ GME | 1 + 3 | 目标召回 ≥85%；Discriminative、Spatial ≥ 基线，且改坏率 < 改对率 | 召回 <60% → SAM 3 提议器；重选改坏 → 只发布阶段 1 |
| K6 | 阶段 3 折叠 | 管线生成的 2k 条轨迹 | 3–5 SFT + 5–10 GRPO | 不低于管线 −2；同报 Faithful@ / Shortcut@ | 掉太多 → 保留管线形态 |

K1 + K2 合计约 1.3 GPU 小时、零 API 花费，就能给出这个机制在 GME 上的天花板；这是 PoC 从没量过的数（PoC 只证明了训进坐标流的 null 不迁移）。

## 5. 与报告的两处不同

1. **候选枚举后置。** 报告的 K2 就用 SAM 3 候选做全管线；我把"只核对基座的框"作为独立的第一阶段，因为它不依赖召回、评测可以完全离线、误拒来源只有一个。枚举和重选是第二阶段，专门为正样本而做。
2. **重选的地位更高。** 用户要的是各维度都提升；否决模式对正样本最多"不伤"，能让 Discriminative / Spatial 上升的只有重选（选错物体是 GME 正样本的主要失败）。所以 K5 不是可选项，是达到"全部提升"的必经之路，只是必须在 K4 通过后、带改坏率门槛地做。

其余五条修正（软 k-of-n 而非取最小、真句误判加权、先否决后重选、召回门、RL 不碰 null）我同意，并已写进 §2–§4。

## 6. 迭代提速（和机制配套）

- **离线扫参**：基座在 GME 的框、核对者对每题的概率矩阵全部缓存；θ、δ、聚合规则、子轴分析都在 CPU 上秒级完成。核对者每改一版只需重跑核对（1,005 次调用，约 20 分钟），不重跑框。
- **子句级开发集**：核对者的主指标是留出场景上的子句 AUROC 和真句误 no 率，几分钟一轮；GME 只在核对者过线后跑。
- **固定 GME 开发子集 + 配对比较**：201 拒答项 + 每类 100 正样本，只报同一条目上的翻转数（150 条抽样上 Discriminative +2.7 在全集是 −3.9 的教训）。全集只给最终候选。
- **批量生成**：评测目前 batch 1；左填充后 batch 8–16 可提 3–5×，核对调用天然可批。
- **不并行训练与评测**（27 GB + 10 GB 互相拖慢 10×）；两个评测可并行。

## 7. 主要风险

- **复合误拒**：真子句 18% 误 no 在 5 条上取最小会成 63% 误拒；所以判决必须是软的、阈值按误拒预算定、unclear 永不等于 no、按物体尺寸分层报。RefCOCO 短句只有 1–2 条子句，单条误判就是误拒，短句必须进校准集。
- **拆句质量**：GME 是人写的 54 词段落，我们的是规整写手句；拆句错则后面全错，抽 50 条人工看。
- **文本捷径转移到核对者**："这个属性对这个类别不常见 → no"。按候选给标签 + 灰裁剪 unclear + 每次评测报灰图行。
- **关系子句**：只看裁剪判不了，必须全图带红框一起给（v2 提示已如此），关系子句单独报。
- **91% 是域内数**：GME 图更大、描述更密、分辨率不同，迁移由 K2 决定，不预设。
- **同源标签**：8B 判决不能当 4B 的训练标签（谱系规则），标签只来自 Gemini + 人工。

## v2（2026-09-24 下午，用户反馈后）：一个模型、固定两轮、"看 → 放大 → 核对 → 答"

用户否决了三次调用的管线形态（太复杂、离领域做法太远）。重读领域论文（ViGoRL、Ground-R1、Vision-R1、H-GRPO、Mini-o3、DeepEyes、Thyme、PixelEyes、MGPO、TwVG、GRIT、Rex-Thinker、VisualPRM/VL-PRM/MM-PRM、Perceval、CVSearch）后的通用认知与新设计见本次对话记录；补充笔记 `research_notes/视觉定位 思维链 工具 训练机制/extra_papers.md`。

设计：单模型，固定两轮。第一轮输出它认为匹配的框（可至多两个）；harness 按原图分辨率裁剪并附回；第二轮逐条写描述细节的 true/false（条数上限 = 子句数），最后一行 JSON（框或 null）。SFT 冷启动用从标签算出的轨迹（框、裁剪、Gemini+人工的逐句判定、按规则得出的答案），不是看着答案写的；GRPO 奖励 = 答案（正样本 IoU≥0.5 得 1；负样本 null 得 1；正样本 null −1；负样本框 0；不可解析 −1）+ 第一轮框的证据项（正样本对目标 IoU，负样本对任一同类实例 IoU，带精度）+ 一致性（答案必须服从判定，违反 −0.5）+ 小权重判定过程项（与子句标签一致，0.3）+ 格式 0.1。护栏：正样本误拒计数、灰图、RefCOCO 短句、跨场景同文本对。先做三步：4B 零样本在裁剪上判子句；两轮格式 SFT 看自家验证与 GME 开发子集；再 GRPO。
