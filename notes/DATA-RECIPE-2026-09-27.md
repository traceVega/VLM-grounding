# 数据配方评审稿：GME 风格的长描述 + 一处细微改假（2026-09-27）

目的：按 FineCops-Ref / LRV-Instruction 的配方（对已验证的真实描述改一处属性、关系、数量或文字），把我们的负样本从"条款库翻转"升级到 GME 风格的多样性与规模。只用自家 OpenImages（CC-BY）图，GME 不进任何 API。

## 现有底子
- 标签矩阵：285 条样本（102 正 / 93 兄弟正 / 90 负）覆盖 114 个场景、488 个实例、1196 行逐条款判定；每条描述 4–7 个条款，改假来自条款库翻转（flip_from / flip_to 已记录）。
- 已有流水线 datagen/：select（CPU 选拥挤场景）→ write（本地 Qwen3.5-9B 写手：描述 + 原子分解 + 一处翻转）→ check（本地 Gemma4-12B 或 Gemini 逐实例逐条款核验，已有"一实例一调用"的批量版）→ listen（Molmo 唯一性）→ report（门控）。
- 之前的 Gemini 3.1 Pro 观察句重写：1589 次调用，404 万输入 token、33 万输出+思考 token，约 8 美元 → 每次调用约 0.005 美元（含一张图）。

## 拟做（三步，全部 API 走 CPU，与 GPU 训练并行）
1. **写手（Gemini 3.1 Pro，每场景 2 次调用）**：
   - 调用 A（描红全图 + 特写）：给出该实例已核验的条款作为"事实清单"，写一段 GME 风格描述：3–5 句、6–10 个细节，允许在事实清单之外补充可见细节（颜色深浅、材质、文字/标志原文、部件、姿态、周边），并输出原子分解（每个细节一行）。
   - 调用 B（无描红的全图 + 分解）：选 3 个不同类型的细节（属性 / 数量或文字 / 关系或位置各一），各改成一个在这张图里对任何实例都不成立的值，输出 3 条改假描述 + 被改行号 + 原值 + 新值。
2. **核验（Gemini 批量版，每实例 1 次调用，每场景约 5 次）**：对场景里每个实例，一次调用核验"描述的全部细节 + 3 个改后细节"，同时让它给出每个细节的观察句（seen 值），这样不用再跑一遍观察句重写。门控沿用：目标实例对原描述全 yes（至多一个 no 则丢弃）；每个改后细节对所有实例都不成立（零满足者）；其他实例至少一个 no（唯一性）。
3. **审核与导出**：我抽 20 个场景人工读（订阅额度，不用 API key）；导出成 long_items（正样本）与 audit_rows（单错行；两错负样本由两处改假零成本组合）格式，进 SFT 与 RL 的 --extra。

## 规模与预算（按上一次的实测单价 ≈ 0.005 美元/次；写手输出更长按 0.008 计）
| 方案 | 场景 | 新增负样本 | 写手调用 | 核验调用 | 预算 |
|---|---|---|---|---|---|
| A：只重写现有场景 | 114 | 342（3 处改假 × 114） | 228 | 570 | ≈ 4–5 美元 |
| B：扩到 300 场景（select 免费，从实例库再选 186 个） | 300 | 900 | 600 | 1500 | ≈ 12–15 美元 |
| C：B + 对 GME 风格再做一轮"两错"与"关系型"改假 | 300 | 1500 | 900 | 1500 | ≈ 15–18 美元 |
上限设 20 美元；用量按场景记账（沿用 checker_api 的 usage 记录），超过预算即停。

## 时间
- 我的实现：写手 prompt + Gemini 写手阶段（复用 checker_api 的调用/并发/记账代码）约 2 小时；核验 prompt 加观察句字段约 0.5 小时；导出约 1 小时。
- 运行：6 并发，300 场景写手约 40 分钟、核验约 1.5 小时；全程不占 GPU。

## 风险与对策
- 写手补充的"事实清单之外"细节可能不真：核验步对每个细节都判，原描述里被判 no 的细节直接删掉再导出（不丢整条）。
- 改后值仍对某个实例成立：零满足者门控丢弃该条改假。
- 风格漂移（GME 是人写的）：只给写手看 GME 的风格说明，不给任何 GME 样本；抽检时对照 GME 的句长与细节数（中位 8 个条款）。
- 负太多会过度怀疑（LRV 的发现）：训练时保持正负约 1:1，新正样本 = 新长描述本身。

建议：先做方案 A 当作试点（≈ 5 美元，一下午），看 RL 一轮后 GME 拒答是否上移，再决定是否扩到 B。

## 方案 A 执行结果（2026-09-27 14:45）
- 花费 4.66 美元（写手 2.49、核验 2.17；670 次调用），比预算低：核验的思考 token 很少。
- 写手：108 景，107 段描述，细节中位数 8，102 景各 3 处改假（属性 136 / 关系 109 / 数量文字 67）。
- 核验（Pro，逐实例批量，每行带观察句）：897 个细节里目标判 no 的 40（4.5%，写手补充的细节偶有不真，已删）；312 处改假里 217 处对所有实例都不成立（零满足者），85 处被门控丢弃（改后值对某实例成立或 unclear），12 处的原细节已被删。
- 导出 458 条：正 95（7 条因其他实例满足全部细节而不唯一被弃）、单错负 206（A 88 / B 50 / C 68）、两错负 157；训练用 gme_style_train.jsonl = 95 正 + 206 单错 + 60 两错（保持正负比例）。
- 人工抽读 20 景（notes 里的 ~/vlmg-results/gme_review.txt）：描述自然、细节具体、改假细微且类型分明；门控把写手出错的细节和"改后仍成立"的改假都拦住了；未发现保留下来的错误样本。
- 已挂入第四轮（v14）：RL3 第 50 步后先筛查检查点，再 SFT4（sft_coa 数据 + 新数据，无 RefCOCO 答案专用样本，照抄段掩码）→ 筛查 → RL4（新数据入池 @120，稠密惩罚）→ 筛查。
