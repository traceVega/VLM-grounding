# 怎么真正提升多模态 grounding 能力（2026-09-06）

方法：44 个 agent。8 个机制 agent 按因果维度调研（只收对照证据），16 个对抗 agent 用两个镜头逐条反驳（**是否因果** / **是否迁移**），3 个迁移分析，4 个算力分层，5 路策略方案，2 位独立评审，1 个完备性批评者，5 个追问。约 2,100 次工具调用，1,280 万 token。

**本轮最重要的部分不是文献调研，是追问阶段在你们自己的 `tables/gme_original.jsonl` 上做的重算。** 它推翻了三个原本要花 GPU 的方向，并把预算指向一个此前没人瞄准的格子。所有本地数字标 P（本轮实算），脚本留在 scratchpad。

---

## 1. 结论先行

**你们模型丢分的结构已经算清楚了，而且和大家默认的假设相反。**

Qwen3-VL-8B 在 GroundingME 804 道正样本上的失败分解（P，本轮重算，与论文 Table 3 在置信区间内一致）：

| 类别 | n | 占正样本 |
|---|---:|---:|
| 框在完全不同的物体上（IoU < 0.05） | **338** | 42.0% |
| 部分重叠（0.05–0.3） | 67 | 8.3% |
| **可细化的擦边球（0.3–0.5）** | **25** | **3.1%** |
| 弃答 | 41 | 5.1% |
| 命中 | 333 | 41.4% |

再往下看那 338 个：**298 个（88.2%）与真值框零像素重叠**，中位中心距 0.171 个图像对角线，而且**框的大小是对的**（模型/真值面积比中位数 1.93，50.3% 落在 0.5x 到 2x 之间）。

一句话：**模型找到了一个大小合理的物体，然后把框放在了错的那一个上。这是目标选择失败，不是定位精度、不是分辨率、也不是坐标格式。**

三个直接推论，都是算术，不需要再做实验：

1. **所有 zoom / crop / SAM 吸附 / 迭代细化的天花板是 +2.49 分**（那 25 个擦边球全救回来），而 GroundingME 自身的配对最小可检测效应是 4.42 分。**这条路在这个 benchmark 上测不出来。** 独立佐证：LFPR 迁移到 RefCOCO 的 Acc@0.9 是 **−0.029**（n=30,969，CI ±0.55，实测的零效应，不是功效不足）。
2. **把所有小目标拉到大目标的水平，最多 +3.34 分。** 而且 338 个错框里有 183 个在 large/XL 目标上——你们分辨最好的 459 个样本里，39.9% 的框放在了错的物体上。像素预算扫描仍值得花那不到 1 GPU 小时，但它是**协议校正**，不是能力杠杆。
3. **坐标格式假设免费关闭了。** 3,856 个发出的坐标全部落在 0-1000 网格的精确整数上（最大残差 2.3e-13），0 个越界、0 个退化。对 338 个错框做变换救援测试：identity 0、swap_xy 0、flip_y 2、方画布缩放 2、flip_x 16（4.7%，对称场景的随机水平）。不用再查了。

**钱应该花在哪里：**两个大格子，**参照物选择**（33.63 分）和**拒绝**（20 分）。前者目前 `team/PLAN.md` 和上一份审计的三个阶段里**没有任何一步瞄准它**。

## 2. 什么真正提升了能力（有对照证据的短名单）

跨约 90 个 benchmark、几百篇论文，**同时通过"匹配数据 / 离靶验证 / 报告回归"三关**的干预只有三类：

| 干预 | 诚实的效应量 | 为什么算能力 |
|---|---|---|
| **拒绝校准 RL（RC-GRPO）** | 在**现代 4B 基座**上 +3.3 Pr / +8.1 N-acc（不是 headline 的 +26.7——那是在一个根本不会输出弃答的 7B 上测的） | 2,000 样本、LoRA、2×A800；从 FineCops-Ref 迁移到没见过的 gRefCOCO 和 D3；**是唯一一篇报告通用能力表的 REC grounding RL 论文** |
| **IoU 奖励 GRPO 的域外迁移** | LISA-Grounding 56.51 → 63.14，同时匹配的 SFT 臂**掉 1.69** | 离靶；但那个 SFT 臂用 1e-6 学习率且 RefCOCO 曲线 600 步平坦，是弱对照 |
| **把定位监督放进视觉编码器自己的预训练** | 冻结探针上 +18.7 RefCOCO | 但离靶检测衰减约 13 倍，放进完整 VLM 后只剩 **+0.84**，且要 10³–10⁴ GPU 小时 |

**其余看起来很大的数字都是别的东西：**

- **格式**（+10 到 +79）。FindIt：Qwen3-VL 在 xyxy 下 69.9 F1，在 cxcywh 下 **0.0**，两者格式遵从率都是 100%；把同一批 cxcywh 输出按角点重新解析回收 50–75 F1。把 Gemini-3.1-Pro 的输出协议从"发坐标"改成"报 8×8 网格格子"，ScreenSpot-v2 从 11.72 变成 **95.20**。
- **Oracle**。迭代自我修正在真值下 +2.4，**在每一个可部署的停止规则下 −11.1**，置信度与正确性相关 r≈0.22。
- **同分布**。ZwZ 在自己管线的 benchmark 上 +20.24，在图像已验证不相交的 MMStar 上 **+2.20**。
- **残废的基线**。GUI-Actor 的 +25.1 是对着一个比同一篇论文自己发布版本低 7–9 分的复现实现测的。

**由此得到的判据：任何单一 harness、单一 benchmark 上小于约 5 分的 grounding 提升，先验应当是"大部分不是能力"。**

## 3. 感知不是瓶颈，读出才是

这是本轮机制调研最强的一致结论，证据是一组**把像素和编码器字面固定住**的对照：

- 一个**完全冻结**的 Qwen2-VL-7B，自己发出的坐标在 ScreenSpot-Pro 上得 **1.6**；用一个 103M 参数的注意力头去读**同一批未改动的隐状态**，得 **22.9**（加验证器 35.8），ScreenSpot 上 73.5。
- 未经改动的 LLaVA-1.5-13B 权重，把它约 1,280 个注意力头中的 **3 个**训练无关地读出来，RefCOCO val 得 **87.2**——高于同族模型在 RefCOCO 上 SFT 之后发出的 81.5。
- CLIP-ViT-L/336 和 576 个视觉 token 完全固定，仅靠坐标格式加数据组织，LLaVA-1.5-7B 从 81.5 走到 87.4，其中 +4.0 来自预测格式、+9.2 来自归一化。

反过来，**编码器本身几乎耗尽了**：在真实 VLM 内部、匹配 LLM/数据/算力的编码器替换只值约 1 分 RefCOCO（CoME-VL 91.73 → 92.57），Molmo 跨 CLIP/MetaCLIP/SigLIP/DINOv2 的跨度 ≤1.6 分。解冻编码器在 RefCOCO P@0.5 上值 **0.0**，在 P@0.9 上值 +6.1——编码器买的是边界精度，不是目标选择。

**Token pitch 也不是硬天花板。** 28 像素 pitch 的硬量化器要求约 19 token 宽的框才能到 IoU 0.9、约 39 token 到 0.95；实测 Ref-L4 Acc@0.9 已经是 55.8，Hi-Token 在只有 5–8 token 宽的物体上报 P@0.95 = 39.0。模型定位精度比 pitch 细约 5 倍。0-1000 网格只在目标小于图像宽度 1.9% 时才在 IoU 0.9 上起约束。

**还有一条机制解释了为什么迭代救不回来**：grounding 错误是在 **prefill 阶段**犯下的，注意力在 t=0 就已经和真值错位，"prefill 阶段引入的错误在 decoding 中很少被纠正"。这同时解释了自我修正为何是 oracle 幻觉、CoT 为何在 GUI 点击和指点上是负的。

## 4. 迁移规律（三条可证伪的规则）

**规则一（迁移大小）：** 迁移大小由基座在目标 benchmark 上的**可寻址误差**决定——即它的错误中由该干预所消除的那个特定失败造成的比例——**与 RL 还是 SFT 无关，与模型规模无关，与任务名无关**。

    域外增益 ≈ (域内增益 / 域内可寻址误差) × 域外可寻址误差

三个区间，24 行证据全部落入其一：

1. **两个 benchmark 有同一个地板 → 比值 ≈ 1，完全迁移（而且多半是协议遵从）。** RC-GRPO 在 Qwen2.5-VL-7B 上：FineCops-Ref 基线 N-acc 5.3、gRefCOCO 6.4，同一个缺陷（不会输出弃答）。域内 +55.8，域外 +65.1，比值 1.17。看起来像惊人的泛化，其实主要是学会了一个输出约定。
2. **基座已在干预的作用点之上 → 迁移为零或负。** Rex-Thinker 和 RexSeek 从 RefCOCOg 87.2–88.8 的基座专门化到 HumanRef，**各掉 4–5 分**。RC-GRPO 在 gRefCOCO N-acc 已经 77.2 的 Qwen3-VL-4B 上只得 +8.1，而 7B 上是 +65.1。
3. **部分共享 → 增益随管线距离单调衰减 3 到 22 倍。** ZwZ：自己管线 +20.24，独立 HR-8K +7.37，MMStar **+2.20**（9.2 倍衰减）。VISTA-30B：ScreenSpot-Pro +13.3，MMBench-GUI L2 +3.1，OSWorld-G **+0.6**（22 倍衰减，**还在 GUI 域内**）。

**规划时按 3 到 10 倍衰减预算。** 一个把 GroundingME 移动 X 的方法，应当预期把独立 benchmark 移动 X/3 到 X/9，把通用 benchmark 移动 X/10。

**规则二（什么会迁移）：** 一个干预跨 GroundingME / Ref-Adv / Ref-L4 严格 IoU / OpenRef 多目标迁移，**当且仅当它改变了模型在 prefill 阶段选择哪个物体**，并且是在一个它没有被优化过的输出协议下测量的。如果增益由 (a) 弃答头、(b) 坐标/格式通道、或 (c) 部署系统执行不了的候选选择步骤承载，就不迁移。

> **协议交换验收测试**（每个杠杆加一次评测就够）：在一个输出接口里训/调（点、标记、掩码），通过另一个接口（框）评测。增益若在交换后存活**且在 Acc@0.75/0.9 上不小于 Acc@0.5**，就是目标选择，会迁移。若只在原生接口存活，或 Δ(Acc@0.5) 远大于 Δ(Acc@0.9)，就是格式遵从，不会迁移。
> 目前通过：PointRL、VLM-R1 GRPO、RC-GRPO。目前证伪：匹配数据 SFT、GroundingME 负样本混合 SFT、迭代自我修正、LFPR 的裁剪阶段。

**规则三（遗忘）：** 离靶回归的大小由 (i) 训练混合的**格式熵损失**乘以 (ii) **权重更新的有效幅度**决定，**而不是**由 SFT 还是 RL、有没有 KL 惩罚、更新多少参数决定。RL 保护通用能力只是副作用：它的 rollout 采自当前策略，因此保留了基座的输出格式分布。一旦奖励或强制 rollout 打破这一点（RC-GRPO 的强制 None、S-GRPO 的真值注入），或者基座在目标任务上 pass@k ≈ 0 因而不存在在策略正样本（GroundingME Rejection，25 个模型里 20 个恰好 0.0），RL 就继承 SFT 的遗忘特征。

三条实用推论：
- **学习率是文献里最便宜的防御，而且没人写进路线图**：全参微调学习率降 10 倍，目标任务只掉 0.19pp，却消除 17.6/32.1pp 的域外回归——在同一张表里两个轴都赢过 LoRA。任何本地 4B LoRA 跑批，都值得加一个 lr=1e-6 全参臂。
- **不要为 KL 正则化做遗忘防御预算**。三个独立来源一致：去掉 KL 不损失保持率、只影响稳定性。
- **通用能力评测套件要改**：MME/MMBench/POPE 是最不敏感的三列。一篇论文里同一批 SFT checkpoint 在 CoT 提示下 MMMU −12.0、无 CoT −8.8，POPE −5.2 vs −0.7——**仅评测提示就让"遗忘"量摆动 7 倍**。

## 5. 不是一个能力，也不是四个缺陷，是两个因子

没有论文在同一批模型上同时报过 GroundingME + Ref-Adv + Ref-L4 + OpenRef + PR-Bench，所以本轮从一手表格拼了两个矩阵自己算相关。

- **PC1（正样本目标 grounding）**：所有正样本指标载荷在一个轴上（GroundingME 内 89.5%，拼接套件上 83.2%）。
- **PC2（拒绝/弃答）**：与 PC1 正交，而且**内部不自洽**——GroundingME Rejection 与 OpenRef N3R 之间相关 **−0.304**。两个拒绝指标彼此都不同意。
- **约一半的原始 benchmark 间一致性是通用 VL 能力，不是那个被命名的技能**（Aug-2026 空间审计对 12 个 benchmark 做残差化，平均 |ρ| 从 0.487 掉到 0.250，超过 0.5 的配对从 34/66 掉到 6/66）。
- **grounding 专门化的后训练会破坏这个共享因子**（平均 ρ 0.82 → 0.20，p=0.021）。这是群体层面的"刷榜"特征。

**三条战略后果：**

1. **把拒绝当作独立项目**，有自己的基座、自己的评测、自己的回归护栏，**永远不要让它的指标进入一个同时含有正样本维度的加权总分**。
2. **正样本那一侧集中打一个机制**——prefill 阶段在同类干扰物之间的目标选择——而不是把力气摊到四个 benchmark 上。一个设计良好的目标选择干预应当同时出现在四个榜上；如果没有，它就是刷榜。
3. **成功的定义要改。** 如果专门化可靠地去相关，那么一个以"GroundingME 总分 ≥ 38.0"为成功标准的计划，可以在底层因子完全没动的情况下达标。整合阶段要加一个**套件一致性检查**：训练后重算跨 benchmark 的秩相关，如果掉了，增益就是 B 类。

## 6. 五个被追问阶段杀掉或改写的方向

这些是免费的（零 GPU 小时，全在已有文件上重算），但它们各自省下若干 GPU 小时或美元：

| 原方向 | 追问结论 |
|---|---|
| 边界细化 / zoom / SAM 吸附（GroundingME 上） | **删除**。天花板 +2.49，低于该 benchmark 4.42 的配对 MDE。只在 Ref-L4 上保留 LFPR，那里 Acc@0.9 波段有 123 个等效样本（+12.24）且 n=45,341 可测。 |
| 小目标像素预算扫描是"最便宜的杠杆" | **降级为协议检查**。天花板 +3.06，现实 +0.8 到 +1.5，而原定"Small 提升 ≥8 分"的停止规则在 n=88 上 MDE 是 14.9——**按原设计根本不可能触发**。改测**弃答率**（基线 34.1%，预期移动约 22 点，n=88 可检测）。 |
| `evaluate.py` 里那个用真值挑坐标读法的 oracle | **不用管**。实算：Acc@0.5 上 +0.10，Acc@0.75/0.9 上分别 **−0.70 / −1.10**。候选 0（把 0-1000 读成绝对像素）在全部 804 个正样本上 Acc@0.5 = 0.00。选择步骤本身在所有 ≥0.5 的阈值上恰好值 0.00 分。 |
| 序数词路由（"第几个""从左数"） | **删除**。8.0 点的差距双比例检验 z=1.47，**p=0.143**，CI [−2.4, +18.3] 含零；分层后完全消失（CMH p≈0.999）。那个 `ordinal` 标志其实是 Counting 的代理。改按**关系从句数量**路由。 |
| 换基座到 Qwen3.5-9B | **取消**。PR-Bench 上那个 +4.3 是八个正样本列**全部 +4.21 ± 0.28**（sd 0.28，极差 1.0）中的一个——统一位移是决策阈值/输出格式变化的特征，不是八项独立技能提升；同时 Qwen3.5 没有独立的 Thinking checkpoint（只有 `enable_thinking` 开关），迁过去就放弃了 Ref-Adv-s 上值 +7.2 到 +15.1 的最大免训练杠杆。 |

**还有一个premise被拆开了：** GroundingME 的 "Spatial" 是**两个任务**，官方 `subtask_l2` 列区分它们而你们的结果文件把它丢了：

| L-2 单元 | n | Acc@0.5 | 错框数 |
|---|---:|---:|---:|
| Spatial / Relationship | 150 | 34.0% | 76（51%） |
| Spatial / Counting | 150 | **23.3%** | **102（68%）** |

178 个 Spatial 错框里只有 76 个是关系性的，**102 个是计数**——"枚举再索引"的算术，机制不同、解法不同。**Counting 占 Spatial 损失的 57%，目前没有任何计划针对它。** 最差的四个 L-2 单元是：Spatial/Counting 23.3、Limited/Small 28.7、Spatial/Relationship 34.0、Discriminative/State 40.4。"Spatial 是最差维度"只有在把好的一半和坏的一半平均之后才成立。

## 7. 建议：先花 5 GPU 小时和 400 美元，再做一个训练押注

### 第一步：五个诊断，全部在本地 5090 上，共约 5 GPU 小时

**1. 读出普查（1 GPU 小时）——两位评审独立指定的同一个实验。**

取那 338 个错框样本（**不是 379；那 41 个弃答属于另一个失败模式，五个方案里有两个把它们算进去了**），在 HF eager attention 下单次前向，抽 k=3 注意力头读出。头的选择**只在 1,000 个 RefCOCO 训练样本上做一次**，五次试验，绝不碰测试图。报三样东西：读出的 pointing-game 命中率、框 IoU（Acc@0.5/0.75/0.9），以及同一批样本上的**两个零假设**——中心先验框和类别无关显著性峰值。按维度分层（Spatial 178 / Limited 101 / Discriminative 59），按尺寸分层（large 109 / medium 96 / XL 74 / small 56 / tiny 3）。

> **预注册阈值，看结果之前定死**：读出命中真值低于 25%，或者没有比两个零假设都高出 10pp，就**停掉整条读出路线**——那说明这 42% 的错框是真实的感知失败，预算应当转向感知、分辨率和数据。高于 30% 就资助下游全部步骤。

为什么是这一个：它是唯一能把"模型看不见"和"模型说不出"在承载 42% 正样本质量的那个群体上分开的实验，而且**没人跑过**——已发表的读出文献（2503.06287）只在 RefCOCO 上报 Acc@0.5，从没碰过未饱和 benchmark 或严格阈值，也从没报过同模型的发出坐标基线。

**2. Thinking 的 oracle 检验（20 GPU 分钟，决定性）。**

Thinking checkpoint 是最大的免训练杠杆（Ref-Adv-s 上 8B Instruct+CoT 52.3 → Thinking 59.5，**而且在 Acc@0.9 上从 19.9 到 27.3**，格式遵从解释不了），但**从没人把它和等算力的采样对照分开**。在 200 个样本上用 Instruct 采 N 个样本（N 匹配 Thinking 的输出 token 数），算 oracle pass@N。**如果 oracle pass@N 低于 Thinking 单遍，搜索就解释不了这个增益，判定为能力，一个选择器都不用建。** 停止规则：oracle 减 greedy 小于 +8，就没有可选的东西，取消所有选择器臂。

注意两点：诚实的单因子对比是 **Thinking vs Instruct+CoT = +7.2**，不是 +12.3（Table 6 里所有 Thinking 行都带 CoT）。另外 **ACS 的选择器阶梯已经存在且预测零效应**：随机挑在全部 8 列里都低于 greedy，MeanBBox 是 −11.3——坐标级聚合不安全。

**在 4B 上先跑，不是 8B**：两个 4B checkpoint（各约 8.2 GB）能同时装进 32 GB，消除顺序跑批和 harness 漂移这个混淆；4B 的 Thinking 增益也更大（Acc@0.5 上 +15.7 vs +12.3），检验功效更好。

**3. Spatial 分解探针（1 GPU 小时），按 Relationship / Counting 拆开跑全部 300 个样本**，不是只跑 178 个失败样本加一个不可能的 100 样本对照。

**4. 像素预算扫描（<1 GPU 小时），并入基线复现**，读**弃答率**而不是准确率。

**5. 买 500 题的人类天花板（约 400 美元）。** 现在就下单，因为它消耗的是日历时间不是算力。GroundingME 的 804 道正样本、PR-Bench、OpenRef、Ref-L4、gRefCOCO、HumanRef **全都没有人类分数**；可比数据集实测歧义率是 13%（ReasonSeg）和 14.2%（OSWorld-G）。在这之前，"未饱和"只意味着"低于 100"，不意味着"低于人类"，而且好几个停止规则可能定在任务本身的噪声地板之下。

### 第二步：一个训练押注

**在属性不符负样本上做 RC-GRPO 式拒绝校准。** 同一张图、同一个编辑器、逐字节相同的表达式，只把使表达式为真的**那一个从句**改假（改颜色、改物体上的文字、改它与锚点的关系）。

为什么是这个格子：**这是前沿实验室用蛮力明确失败过的一格**。Jedi 生成了 2,666,124 个合成拒绝样本，在 OSWorld-G Refusal 上得 **7.4/100**——与完全没有拒绝训练的 OS-Atlas-7B **分数相同**。而有效的结果用了 **2,000 个样本、两张卡**。杠杆是目标函数，不是语料。GroundingME 自己的 30k SFT 扫描买到 Rejection 27.9，代价是 Discriminative 从 61.3 掉到 40.2、Limited 从 36.0 掉到 17.0。

而且这正是你们的编辑机器独有装备的方向，也是 `BENCHMARK-LANDSCAPE.md` 已经标出的那个空白格。

> **三部分停止规则，必须同时满足**：GroundingME Rejection ≥ 10.0（n=201，CI ±6.2，所以低于约 13 都和零区分不开）**且**任何非拒绝维度掉幅 ≤ 2.0 **且** RefCOCOg val 掉幅 ≤ 1.0。**每个 Rejection 数字旁边必须报解析失败率**——官方 scorer 把无法解析的输出算作正确拒绝。

### 不要做的

- 不要在 GroundingME 上花任何 GPU 做边界细化。天花板 +2.49，MDE 4.42。
- 不要把小目标分辨率当能力杠杆宣传。天花板 +3.34，且 338 个错框里 183 个在大目标上。
- 不要再查坐标缩放。3,856 个坐标全是精确的 0-1000 整数，已免费关闭。
- 不要为 `evaluate.py` 的 oracle 做减法。实测 +0.10，严格 IoU 上还是负的。
- 不要按序数词路由 Thinking。p=0.143，是 Counting 的代理。改按关系从句数量。
- 不要迁到 Qwen3.5。统一位移 +4.21±0.28，且失去 Thinking checkpoint。
- 不要把 MME/MMBench/POPE 当通用能力回归套件——它们是最不敏感的三列。加 DocVQA、AI2D、MathVista、CharXiv。
- 不要为 KL 正则化做遗忘防御预算。改用低学习率加格式多样的 replay。
- 不要把 Rejection 和正样本维度放进同一个加权总分。它们是正交因子，两个拒绝指标之间相关 −0.304。
- 不要指望本地 4B 的结论直接授权 8B 的结论——但反过来，4B 上的 Thinking 检验功效更好，先在那里做。

## 8. 未解决的问题

1. **人类天花板仍然缺失**（见第一步第 5 项）。这决定整个项目值不值得做。
2. **没有任何 2026 前沿模型在 GroundingME / Ref-Adv / Ref-L4 / OpenRef 上有公开数字**。所有"未饱和"判定只对 2025 代模型成立。用 API 跑一次几十美元就能定性。
3. **RefBench-PRO 71.4 与 PR-Bench 59.4 的 12 分矛盾未解决**。同一批作者、评审判定两个指标定义逐项相同。
4. **注意力读出在严格 IoU 下能不能用有分歧**：一个方案要求在 Acc@0.5/0.75/0.9 上都打分作为核心新颖点，另一个方案说该方法产生的框来自高斯平滑加均值阈值二值化，"给不出紧的外接框，不该在 0.9 上打分"。第一步的普查会顺带回答这个。
5. **Counting 这一格（102 个错框，Spatial 损失的 57%）目前没有任何机制假设**。本轮八个机制维度里没有一个覆盖"枚举再索引"。
6. **没人在 GroundingME 旁边报过 MMStar / MMMU / DocVQA**，所以 grounding 因子从来没有像空间套件那样对通用能力做过残差化——"一个 grounding 能力"可能有一半是"一个好模型"。
