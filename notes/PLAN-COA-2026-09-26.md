# 执行计划：提议 → 逐候选观察与判断 → 模型自答（COA v2），2026-09-26 晚定稿

宗旨：尽快迭代方法到理想效果；细枝末节后置或不做。设计定稿见 REDESIGN-COA-2026-09-26.md（评审）与 REVIEW-COA-V2-2026-09-26.md（审核）。

## 方法（定稿）
- 第一轮（可训练）：全图 + 描述 → `<conditions>` + 一次 `image_zoom_in`，≤ 6 个候选框，最可能的排第一。
- 系统：每个候选裁一次原分辨率特写（外扩 25%，短边 ≥ 512），并生成一张该候选描红的全图；上下文只用这两张图（描红全图作第一轮的图，特写作第二轮的图）。
- 第二轮（逐候选隔离、批量）：`j. <声称> | seen: <看到> | match/mismatch/unsure` 每条款一行 + `<verdict>`；无类型标签，无候选序号提示，无任何豁免规则。
- 第三步（纯文本）：把 K 个审计块和框坐标给模型，模型自己写 `<answer>`；这是主指标。
- 规则推导答案只用于：标签一致性断言、RL 一致性门、评测诊断（忠实度差）。named 判定：去否定词与停用词后，seen 的实词不是声称实词的子集。
- SFT：第一轮样例 + 每个标签行一个审计样例 + 每条样本一个答案样例；seen 来自翻转精确值 / 核对观察句 / 同实例其他 yes 条款的槽值；无反值的 no 格渲染为 unsure；重渲后断言"标签判决 = 规则推导"100%。单错审计行 ≥ 40%，负样本两错占两到三成，去重，mask 照抄段。半场景 SFT。
- RL（GRPO，组 8，无 KL，优势不除 std，正负 1:1，分段优势）：格式 +0.1/−1（0 框 −1，单个审计不可解析记 unsure 并 −0.2）；一致性门：模型答案 ≠ 规则推导 → 结果项 0；正样本：框 IoU ≥ 0.5 → +1，错框 0，空答 0；负样本：空答 → +0.5，且仅当某候选命中被描述实例、其审计把 mismatch 落在被改假条款且 seen 含原值实词（多错样本按比例）；无标签负样本封顶 0.5、比例压低；误控（正样本标签实例的审计出现 named mismatch）−0.5。注入：组内无人拿到结果分。停机只看自家验证集与自家灰图；mini-GME 只记录。
