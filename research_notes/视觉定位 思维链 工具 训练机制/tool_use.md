# Agentic "thinking with images" (crop / zoom / mark tools) in VLMs, 2025–2026: recipes, numbers, and what it buys for fine detail, small objects and grounding

Scope note: all numbers below were extracted from arXiv HTML full texts (or the GitHub README where stated) on 2026-09-23. Benchmarks: V* Bench = 191 SA-1B images (avg 2246×1582), 115 attribute + 76 spatial questions ([V*/SEAL](https://arxiv.org/abs/2312.14135)); HR-Bench = 200 images in 4K (avg 4032 px) and 8K (avg 7680 px) versions, split into Fine-grained Single-instance Perception (FSP: attribute, OCR, visual prompting) and Fine-grained Cross-instance Perception (FCP: maps, charts, spatial) ([HR-Bench/DC²](https://arxiv.org/abs/2408.15556)); MME-RealWorld-Lite = 1,919 questions ([MGPO](https://arxiv.org/abs/2507.05920)). Baselines for the same base model differ by up to ~13 points across papers because of max-pixel settings and Avg@N protocols (see Q0 inferences), so compare deltas within a paper, not absolute numbers across papers. Items marked **[unverified]** came from an automated extraction that I could not cross-check.

## Q0. Paper-by-paper recipes: tool interface, cold-start synthesis, RL reward, size, compute, gains

### Takeaway
Nearly the whole 2025 line is Qwen2.5-VL-7B + GRPO with a bbox-crop tool whose output is re-encoded and appended as new image tokens; the recipes differ mainly in (a) whether a cold-start SFT is used (DeepEyes and MGPO skip it, most others use 3K–500K synthetic trajectories), (b) how tool use is kept alive during RL (conditional tool bonus, curiosity bonus, fixed-turn template, over-turn masking), and (c) reported V* gains of +5 to +19 points over a 71–78 baseline, with HR-Bench 8K gains of +6 to +12 and MME-RealWorld gains of +5 to +11.

### Cited Findings

**DeepEyes (May 2025)**
- Tool: crop by `[x1, y1, x2, y2]` (top-left, bottom-right) with optional label; crops "appended to the ongoing trajectory"; up to 6 active-perception steps per query — [DeepEyes](https://arxiv.org/abs/2505.14362)
- No SFT cold start. RL data ≈47K: V* train 22K (47%), ArxivQA charts 14K (30%), ThinkLite-VL 11K (23%); three filters (difficulty, label verification, "perception-utility filter, retaining only samples solvable via active perception with ground-truth regions") — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Reward: `R = R_acc + R_format + 1[R_acc>0]·R_tool`, i.e. the tool bonus is paid only when the answer is correct and at least one tool call occurred; GRPO, 256 prompts/batch, 16 rollouts/prompt, max response 20,480 tokens, KL = 0, 80 iterations on H100s — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Hardware per README: "no less than 32 GPUs (4 nodes x 8 GPUs) for 7B training, and no less than 64 GPUs ... for 32B", ≥1200 GB CPU RAM per node, verl-based, `max_turns` 50 configurable — [DeepEyes GitHub](https://github.com/Visual-Agent/DeepEyes)
- Results (7B): V* 90.1 vs 71.2 base (+18.9); HR-Bench 4K 75.1 (+6.3); HR-Bench 8K 72.6 (+7.3); MME-RealWorld(-Lite) 53.2 vs 42.3 (+10.9); POPE 87.7 vs 85.9; MathVista 70.1 (+1.9); WeMath 38.9 (+4.3) — [DeepEyes](https://arxiv.org/abs/2505.14362)
- RefCOCO/+/g "minor gains (+0.6–1.0)" and response length 212→241 tokens — **[unverified: extraction only; I could not confirm a REC table exists in the paper]** — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Tool-reward ablation (Table 5): no tool reward 87.4 V*; unconditional tool reward 87.4; conditional 90.1. Text-only RL CoT vs interleaved (Table 9): HR-8K 60.8 vs 72.6 — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Independent re-evaluations of the released DeepEyes checkpoint are lower: V* 83.3 / HR-4K 73.2 / HR-8K 69.5 / MME-RW 64.0 under Mini-o3's Avg@N protocol — [Mini-o3](https://arxiv.org/abs/2509.07969); V* 75.9 / HR-4K 63.9 / HR-8K 62.0 at a 1,024-visual-token budget — [LFPC](https://arxiv.org/abs/2603.27494)

**DeepEyesV2 (Nov 2025, v2 Mar 2026)**
- Tools: sandboxed code for crop / mark / rotate / enhance / resize / numeric ops, plus SerpAPI image search (top-5 visually matched pages) and text search (top-5 pages); "All tool outputs are converted into observations and appended to model's context"; RL max response 16,384 tokens — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- Direct RL from Qwen2.5-VL-7B failed: the model "gradually abandons code generation and converges to producing only short reasoning chains", and reward-hacked by "emitting exactly one code block per query" of "non-executable, placeholder comments" — motivating a cold-start stage — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- Cold start: prompts from V*, ArxivQA, Pixmo Counting, TallyQA, SeekWorld, ReVisual, MathCoder, Retool, MMSearch-R1, VGR, Chain-of-Focus, VLM-R3; trajectories generated by Gemini 2.5 Pro, GPT-4o, Claude Sonnet 4 with real tool execution fed back; difficulty filter keeps items the base model "answers correctly at most two times"; SFT 3 epochs, lr 1e-5, batch 128 — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- RL: DAPO, `R = R_acc + R_format` only ("without complex reward engineering"), batch 256, 16 rollouts, KL 0, clip 0.20/0.30, lr 1e-6 — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- Results (7B): V* 81.8 vs 78.5 base (+3.3); HR-4K 77.9 vs 71.6 (+6.3); HR-8K 73.8 vs 67.9 (+5.9); MME-RealWorld 64.9 vs 57.3 (+7.6); MathVerse 52.7 (+7.1); RealX-Bench integration 18.1 vs 6.9 base vs 9.7 DeepEyes v1 (human 51.4); MMSearch 63.7 vs 53.8 MMSearch-R1 — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- Tool invocation rate drops "significantly" after RL; perception tasks mostly use crop, charts/math use arithmetic, search tasks use search — [DeepEyesV2](https://arxiv.org/abs/2511.05271)

**Pixel Reasoner (May 2025)**
- Tools: `CropImage(bbox [x1,y1,x2,y2], target_image)` and `SelectFrames` (≤8 of 16 frames); outputs concatenated into the trace — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- Warm-start SFT: 7,500 trajectories (5,500 pixel-space + 2,000 text-space) written by GPT-4o from templates using SA1B masks, FineWeb page boxes and STARQA temporal windows; "error-induced" trajectories insert a wrong crop/frame before the correct one (recrop once/twice, further zoom, reselect); loss masked on tool outputs and on the erroneous operations — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- RL: `r' = r + α·max(H − RaPR(x), 0)·1_PR(y) + β·min(N − n_vo(y), 0)` with H = 0.3, N = 1, α = 0.5, β = 0.05 (max curiosity bonus ≈ 0.0875, −0.05 per extra operation); GRPO with selective sample replay, 8 samples/query, batch 256; 8×A800 for 20 h — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- Results (7B): V* 84.3 vs 79.0 (warm-started model without RL) **[baseline identity per extraction]**; TallyQA-Complex 73.8 vs 67.9; InfographicsVQA 84.0 vs 74.3; MVBench 67.8 vs 59.0. Ablations: no curiosity 81.1; no warm start 81.7; no correction data 80.1 — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- Tool-use rate at inference: V* 78.5%, TallyQA 57.8%, InfoVQA 59.0%, MVBench 67.0% — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)

**Chain-of-Focus (v1 May 2025; "Adaptive CoF" latest version)**
- Tool: bbox `[x1,y1,x2,y2]`; pipeline crops, "enlarging them by a factor of two", re-encodes with the ViT, appends region tokens — [Adaptive CoF](https://arxiv.org/abs/2505.15436)
- v1 data: MM-CoF 3K from 360 SA-1B images upscaled to 4K; GPT-4.1 wrote 4 questions/image, filtered by GPT-4.1 vs Qwen2.5-VL-72B agreement; 2,201 need zoom, 2,294 answerable directly; resolution ladder {224…3840}; SFT freezes ViT, LoRA on projector + LLM; RL = GRPO with `r = r_correct + r_format`; 4×A100, 38 h (6 h SFT + 32 h RL) — [CoF v1](https://arxiv.org/abs/2505.15436v1)
- v1 results (7B): V* 88.0 vs 80.0 base; by input resolution, V* base/CoF: 224 px 40.4/42.9, 672 px 60.7/70.7, 1024 px 71.7/73.9, 2560 px 80.3/88.2, 3840 px 84.1/89.3; TextVQA 81.8 vs 83.6 (drop); POPE 88.4 vs 86.2; grounding accuracy SFT 0.82 → RL 0.86 — [CoF v1](https://arxiv.org/abs/2505.15436v1)
- Adaptive version: 5K SFT (LoRA rank 32, lr 1e-5, 3 epochs) + 10K RL samples (1,500 proprietary + VisDrone, ArxivQA, ThinkLite-VL); Adaptive Group-Aware Reward: correct direct answer = 1, correct zoom path = 1−δ with δ = 0.2 when a direct solution exists, format γ = 0.1; SFT 4×A100 ~6 h, RL 8×A100 ~32 h — [Adaptive CoF](https://arxiv.org/abs/2505.15436)
- Adaptive results (7B): V* 90.1 vs 71.2 (attr 92.2 vs 73.9; spatial 86.4 vs 67.1); HR-4K 73.5 vs 68.8; MME-RealWorld 50.9 vs 42.3; POPE 89.3 vs 85.9; TallyQA 75.0 vs 68.6; SFT alone already 89.5 on V*; RL with correctness+format only "degrades performance; model avoids zoom-in"; on HR-4K uses 5.4% of DeepEyes' visual tokens with 77.8% fewer zoom-ins; average 2.5 zoom calls at 224 px input falling to 0.52 at 2560 px — [Adaptive CoF](https://arxiv.org/abs/2505.15436)

**Mini-o3 (Sep 2025)**
- Tool: action = grounding (normalized bbox in [0,1]², source = original image or any prior observation) or final answer; training cap 6 turns at 32K context; inference scaled to 32 turns; max pixels cut from 12M to 2M — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Data: VisualProbe 4,000 train / 500 test (small targets, distractors, high-res); cold start = ~6,000 trajectories obtained by few-shot prompting an existing VLM with 6 hand-written exemplars, keeping only correct-answer trajectories — [Mini-o3](https://arxiv.org/abs/2509.07969)
- RL: GRPO with clip-higher, dynamic sampling, token-level loss; 16 samples/query, batch 256, lr 1e-6, no KL/entropy; LLM-judge reward; over-turn masking removes the implicit penalty on truncated trajectories; cutting the turn budget 16→6 "shortens a 10-day training run to about 3 days" — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Results (7B, Avg@N): V* 88.2; HR-4K 77.5; HR-8K 73.3; MME-RW 65.5; VisualProbe hard/medium/easy 48.0/50.4/67.0 vs DeepEyes 35.1/29.8/60.1 vs Pixel Reasoner 28.8/29.6/58.4 vs base 23.9/26.0/39.1 — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Ablations (VisualProbe-hard): over-turn masking 44.4% with 5.5 avg turns vs 32.2% with 3.0 turns without; max pixels 0.5M/1M/2M/12M → 36.4/44.4/48.0/36.1 with avg turns 6.7/5.5/5.6/1.0 (12M "collapsed" to one turn); no cold-start SFT → 25.4%; without masking >20% of early-training responses were over-turn — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Turn distribution with masking: 9.4% 1–4 turns, 53.3% 4–8, 32.4% 8–16, 2.1% 16–24, 0.1% 24–32 — [Mini-o3](https://arxiv.org/abs/2509.07969)

**Thyme (Aug 2025)**
- Tool: model writes Python in `<code>` tags; sandbox (10 s timeout) executes crop/rotate/enhance/compute; results returned in `<sandbox_output>`; sandbox auto-clamps crop coordinates to image bounds and keeps variables across turns; capped dialogue turns — [Thyme](https://arxiv.org/abs/2508.11630)
- SFT 500K: 100K direct answers, 50K real-world code samples filtered from 4M+, 28K crops from V* with GT boxes, 14K rotation, 10K contrast enhancement, 15K computation; Qwen2.5-VL-72B judged code necessity and verified outcomes, GPT-4o converted math code; "train on the last round only" and sandbox-output masking; RL data 10K manually annotated high-res QA (objects <5% of image, 15 annotators) plus V*/ArxivQA/ThinkLite-VL — [Thyme](https://arxiv.org/abs/2508.11630)
- RL: GRPO-ATS (temperature 1.0 for text, 0.0 for code); `r = Result × (1 + 0.5·Consistency) + 0.5·Format`; adding a process reward hurt (62.91 vs 63.59 avg) and a code reward "encourages unnecessary code" (64.54); consistency reward best (65.68); SFT-only 62.01 vs SFT+RL 65.68 average — [Thyme](https://arxiv.org/abs/2508.11630)
- Compute: 32×H800; extraction reports "~224 GPU hours" for SFT and ">1200 GPU hours" for RL — **[the two figures conflict in the extraction; treat as unverified]** — [Thyme](https://arxiv.org/abs/2508.11630)
- Results (7B): V* 82.2 vs 76.4; HR-4K FSP 91.0 vs 85.2; HR-8K FSP 86.5 vs 78.8; MME-RW perception 67.1 vs 60.6, reasoning 48.4 vs 38.6; OCRBench 86.3 vs 88.4 (drop) — [Thyme](https://arxiv.org/abs/2508.11630)

**MGPO (Jul 2025)**
- Interface: fixed two-turn template — turn 1 must output `[x1,y1,x2,y2]`, the crop is returned, turn 2 answers; coordinates rescaled from the resized input back to the original ([x̂] = [x]/S_input × S_ori); zero-shot generalizes to 3 turns — [MGPO](https://arxiv.org/abs/2507.05920)
- No SFT, no box labels: binary answer reward only; the fixed template exists because "LMMs struggle to autonomously trigger visual grounding during the rollout process"; 21,690 MME-RealWorld training samples; 4 nodes × 8 H100, lr 1e-6, batch 512; also run on the 3B model — [MGPO](https://arxiv.org/abs/2507.05920)
- Results (7B): V* 76.4 vs GRPO 71.2 (+5.2) vs SFT 71.7; MME-RW 60.5 vs GRPO 55.1; 65.2% of MGPO crops suffice to answer vs 47.1% base and 50.2% GRPO; valid-coordinate rate rises to ~65% during RL while staying low for GRPO — [MGPO](https://arxiv.org/abs/2507.05920)

**Simple o3 (Aug 2025)**
- Tools: `focus_area` (bbox → crop at inference), `zoom_in` (whole-image interpolation), `reuse` (re-insert original image); observations appended between `<observation>` tags; max rounds M — [Simple o3](https://arxiv.org/abs/2508.12109)
- Data: teacher Gemini-2.5-Flash-Preview in an observe-reason-act loop, verified by Gemini-2.5-flash-lite and Qwen3-turbo (geometric validity + semantic consistency, ≤2 attempts); 150K candidates → ~100K retained (dataset is named TWI-Tools-146K) **[count discrepancy in extraction]**; sources MATHV360K, LLaVA-CoT-100K (27K COCO QA), ArxivQA (19K) — [Simple o3](https://arxiv.org/abs/2508.12109)
- Training: SFT only, full-parameter, 1 epoch, seq 8,192 — [Simple o3](https://arxiv.org/abs/2508.12109)
- Results (7B): V* 90.4 vs 77.5 base; HR-4K 76.2 vs 68.8; tool ablation: `reuse` alone +4.8 V*, `zoom_in` ≈ +1, `focus_area` +6.9 V* and +4.9 HR-4K; training with bbox-only (no crop) "performs worse than cropping" because of redundant visual tokens — [Simple o3](https://arxiv.org/abs/2508.12109)

**OpenThinkIMG / V-ToolRL (May 2025)**
- Tools as containerized services: GroundingDINO, SAM, OCR, Crop, Point, DrawHorizontalLineByY, DrawVerticalLineByX, ZoomInSubplot, SegmentRegionAroundPoint; a controller dispatches calls and appends outputs — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)
- Cold start: 1,471 GPT-4o tool trajectories (5 demos, T = 0.7) + 1,471 text CoT from ChartGemma (14,501 train); filtered by Qwen2-VL-72B, rule checks and humans; 2 epochs lr 2e-5 — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)
- RL: GRPO, reward +1/−1 on final answer only, KL β = 0, 500 steps, lr 1e-6, batch 144, 4–8 A100 — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)
- Results (Qwen2-VL-2B, ChartGemma test): base 29.56 → SFT 45.67 → text-only RL 51.63 → V-ToolRL 59.39; GPT-4.1 50.71; Gemini-2.0-flash 68.20; tool calls per sample fall from ~0.63 to 0.10–0.12 by step 250–300 — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)

**Visual-ARFT (May 2025)**
- Tools: `<code>` for crop/rotate/etc., `<search>` via Serper; 1,200 coding examples from synthetic distortions of OCRBench-v2, RICO, DocVQA; 20 hand-written search examples; `R = R_format + R_acc` (F1 for answers, semantic similarity for queries, constant 1 for code blocks); GRPO, 8 GPUs, 8 generations/update; Qwen2.5-VL-3B and 7B — [Visual-ARFT](https://arxiv.org/abs/2505.14246)
- Gains: MAT-Coding F1 +8.01 (3B) / +18.56 (7B); MAT-Search +5.66 / +10.28; MAT-Coding Hard +10.44 (3B) vs +25.93 (7B); 3B "outperforms GPT-4o on the MAT-Coding task" — [Visual-ARFT](https://arxiv.org/abs/2505.14246)

**Active-O3 (May 2025)**
- Two-stage: policy emits up to K = 3 JSON boxes `{"bbox_2d":[x1,y1,x2,y2],"label":...}` in one pass; a task model runs on each crop; reward = task AP/AR@0.5 or mIoU + format + non-overlap (IoU ≤ 0.3) + area 1–50% + coverage, all weights 1.0; GRPO β = 0.04, group 8, lr 1e-6; 10K LVIS images; 8×80–90 GB GPUs, 24 h — [Active-O3](https://arxiv.org/abs/2505.21457)
- Small-object detection: SODA-D AP_s 8.0 (GroundingDINO) → 15.1, AR_s 8.7 → 22.0; SODA-A AP_s 0.7 → 9.2; LVIS_small 1.2 → 2.2; LVIS_dense 1.6 → 4.3; zero-shot RealWorldQA 67.9 → 69.7; ~2.5 s for the proposal pass then K task passes, vs "over 10 MLLM forward passes per image" for V*+GDINO — [Active-O3](https://arxiv.org/abs/2505.21457)

**ViGoRL (May 2025)**
- Single-turn: each step is ⟨thought, (x,y)⟩; multi-turn: `<tool_call>{"name":"crop","arguments":{"coordinate":p}}` returns a w×w crop resized to r×r in `<observation>`; cold start = MCTS with frozen Qwen2.5-VL-72B, 1,500 prompts → ~30K traces; GRPO with `R = λ_fmt·r_fmt + λ_task·r_task`, multi-turn adds +0.2 per distinct coordinate (≥10 px apart, up to 4) — [ViGoRL](https://arxiv.org/abs/2505.23678)
- Results: V* 3B 74.2 → 79.1; 7B 78.0 → 86.4 (multi-turn zoom); ScreenSpot-Pro 3B 23.9 → 31.1 (multi-turn 32.3), 7B 29.0 → 33.1; ScreenSpot-V2 3B 68.4 → 86.5, 7B 73.6 → 91.0; SAT-2 3B 46.1 → 62.9; removing grounding −4.3 SAT-2 / −3.1 BLINK; pointing vs variable boxes identical on V* (81.2 both) — [ViGoRL](https://arxiv.org/abs/2505.23678)

**VLM-R³ (May 2025)**
- `{"bbox_2d":[x1,y1,x2,y2]}` triggers crop → zoom → re-encode → append; R-GRPO computes gradients only on text and bbox tokens; VLIR 11,810 samples (GQA 4,057, TextVQA 3,267, DocVQA 1,497, InfoVQA 1,497, VSR 1,492) from Qwen2.5-VL-72B + rejection sampling; reward = 1 accuracy + 1 format + 0.5 region validity (cap 0.5) + length 0.001/char (cap 0.25); SFT 4×A100, RL 6×A100 — [VLM-R³](https://arxiv.org/abs/2505.16192)
- Results (7B): ScienceQA 87.9 vs 73.6; MathVision 30.2 vs 25.1; MMMU 62.2 vs 58.6; DocVQA 96.8 vs 95.7; ScienceQA falls to 54.1 when region grounding accuracy is forced to 40% (vs 87.9 at 90%) — [VLM-R³](https://arxiv.org/abs/2505.16192)

**Argus (CVPR 2025)**
- Grounded CoT: predict normalized `[xmin,ymin,xmax,ymax]`, then either RoI re-encoding (square-padded crop through the encoders → 1,024 new tokens, 827 ms) or RoI re-sampling (cached patch embeddings, ~26 tokens, 492 ms); Llama-3-8B + CLIP/ConvNeXt-XXL/EVA-02 experts; SFT ~3.8M samples incl. VCoT 436K, GRIT 756K, Shikra 326K — [Argus](https://arxiv.org/abs/2505.23766)
- V*: implicit attention 58.6 → text-only box guidance 63.9 → RoI re-encoding 68.1 / re-sampling 67.0; Eagle-X3 baseline 55.3 → +CoT signals 62.7 → +grounding 67.0; multi-RoI 78.5; RefCOCO val 89.8, RefCOCO+ val 84.7, RefCOCOg test 85.2 — [Argus](https://arxiv.org/abs/2505.23766)

**GThinker (Jun 2025)** — cue-rethinking with `<vcues_*>` tags, no crop/zoom tool; 7K cold start + 4K RL (DAPO); Qwen2.5-VL-7B, 32 H100, ~9 h; M3CoT 81.5 vs 62.4, MathVista 72.7 (+4.5), MMStar 66.4 (+2.5); no V* result — [GThinker](https://arxiv.org/abs/2506.01078)

**VITAL (video, Aug 2025)** — clip tool takes start/end timestamps and returns densely sampled frames via JSON `<tool_call>`; MTVR-CoT-72k (Gemini 2.5 Pro) + MTVR-RL-110k (tool parameters = GT + 20% noise); DGRPO with accuracy (IoU/EM/ROUGE) + 0.5 format + 0.5 tool-success rewards; Qwen2.5-VL-7B, 640 GPU-hours; LongVideo-Reason 79.3 vs 67.9 prior best; VidChapters-7M R@0.5 34.7 vs 27.4 — [VITAL](https://arxiv.org/abs/2508.04416)

**V-Thinker (Nov 2025)** — code-driven interaction over 61 abstracted tools; V-Interaction-400K + V-Perception-40K generated by GPT-5, checked by Qwen3-VL-235B, repaired by GPT-4.1; SFT then GRPO with `R = R_acc + 0.5·R_format + 0.3·1[R_acc>0]·R_tool`; 512 H20 GPUs; VTBench avg 30.2 vs 17.7 base — [V-Thinker](https://arxiv.org/abs/2511.04460)

**LFPC — Learning to Focus and Precise Cropping (CVPR 2026)**
- "Information gap" data: downsample the input until the model's answer diverges from the high-res answer, keep crops from the original (2.5 A100-h offline selection); Stage-I `r = r_acc + r_format + 1[r_acc>0]·r_tool`; Stage-II geometric reward on 256 VisualProbe boxes with hierarchical GT (`r_IoU` gated by coverage τ = 0.9, `r_l1 = 1 − L1`, `r_geo = ω·r_IoU + (1−ω)·r_l1`); Qwen2.5-VL-7B, 8×A100, 80 steps, 320 + 96 A100-h — [LFPC](https://arxiv.org/abs/2603.27494)
- At 1,024 visual tokens: HR-8K 72.1 (FSP 83.3 / FCP 60.8) vs DeepEyes 62.0, Mini-o3 66.0, CoF-SFT 58.9; HR-4K 75.3 vs 63.9 / 70.7; V* 80.6 vs 75.9 / 80.1; at 16,384 tokens 75.4 / 76.4 / 89.5; crop IoU on HR-8K FSP 29.8 → 34.5, FCP 39.3 → 44.4; 2.8 s per HR-8K image vs 12.4 s DeepEyes; baseline ~4.5 tool calls/question rising to ~10–12 after Stage-I — [LFPC](https://arxiv.org/abs/2603.27494)

**Learning to Zoom Efficiently with a Contrastive Curriculum (Sep 2026)**
- Single zoom call; coordinate formats: absolute pixels (Qwen2.5-VL), [0,1] (Gemma 4), 0–1000 promille (InternVL 3.5); no SFT; `r = r_acc + 0.1·1[correct]·r_tool` with an InfoNCE-style tool reward comparing the post-zoom reasoning likelihood under the chosen zoom vs an automatically generated negative zoom whose IoU with the positive rises from 0 (first 30% of steps) linearly to 0.175; 6,698 queries; GRPO, 8×A100, ~35 h/epoch — [Contrastive zoom](https://arxiv.org/abs/2609.03206)
- Results (Qwen2.5-VL-7B): V* 85.34 (89.01 with VisualProbe continual RL) vs Mini-o3 86.91 vs base 72.25; HR-4K 78.50/79.12 vs 77.73 (Mini-o3) / 77.90 (DeepEyesV2) / 57.75 base; HR-8K 73.38/73.00 vs 73.39 / 73.80 / 50.88; MME-RW 64.38/67.10 vs 65.63 / 64.90 / 49.38; Mini-o3 needs 16 tool calls to overtake the one-call model; training cost 35.9 h vs 24.7 h no-tool (+46%) — [Contrastive zoom](https://arxiv.org/abs/2609.03206)

**Qwen3-VL (Nov 2025)** — "thinking with images" trained in two stages: ~10K two-turn grounding SFT examples, then multi-turn tool-integrated RL; sizes 2B/4B/8B/32B dense + 30B-A3B/235B-A22B; coordinates normalized to [0,1000]; V* 93.7 / HR-4K 85.3 / HR-8K 82.3 reported for the 235B flagship only — [Qwen3-VL report](https://arxiv.org/abs/2511.21631)

**Survey taxonomy** — three stages: (1) tool-driven visual exploration (MM-REACT, ZoomEye, DeepEyes, Active-O3; prompt/SFT/RL variants), (2) programmatic visual manipulation (VisProg, ViperGPT, Visual Sketchpad), (3) intrinsic visual imagination; challenges listed: "explosive token economy of visual thought", "one flawed image versus a thousand wrong words", language–pixel bottleneck, and no single strategy fits all tasks — [Survey](https://arxiv.org/abs/2506.23918)

### Inferences
- Reported baselines for Qwen2.5-VL-7B on V* range from 71.2 ([DeepEyes](https://arxiv.org/abs/2505.14362)) to 84.1 at 3840-px input ([CoF v1](https://arxiv.org/abs/2505.15436v1)); the headline "+19 points" claims are measured against the low-resolution setting, and the gap between a tool-trained 7B and a plain 7B fed the full-resolution image is closer to +5 (89.3 vs 84.1 in CoF's own table).
- Two rounds of independent re-evaluation (Mini-o3, LFPC, contrastive-curriculum) put DeepEyes 4–14 points below its paper numbers while Mini-o3 reproduces within ~1.3 points; DeepEyes is the least reproducible anchor in this literature.
- Every recipe that skips SFT (DeepEyes, MGPO, contrastive curriculum, LFPC Stage-I) needs some other device to keep tool calls alive: a correctness-conditioned tool bonus, a forced-turn template, or a contrastive tool reward.

### Gaps
- Training wall-clock/GPU counts are absent for Mini-o3, ViGoRL, and DeepEyesV2 in the extracted text.
- MME-RealWorld numbers are not comparable across papers (42.3 / 49.4 / 57.3 base for the same model) and the extracted subsets (lite vs full, perception vs reasoning) are often unstated.
- DeepEyes' REC rows and token statistics could not be verified.

## Q1. Does a zoom tool measurably improve fine-grained attribute verification versus the same model at global resolution, and who isolates it?

### Takeaway
Yes at the benchmark level, but the cleanest 2026 decomposition finds that only ~22–30% of the tool-RL gain is attributable to the tool itself (the rest is intrinsic, tool-free improvement), and several papers show that the crops of RL-trained models are often not what the answer depends on; the strongest isolated evidence for the tool per se comes from interleaved-vs-text-only ablations (+11.8 HR-8K in DeepEyes), tool-family ablations (Simple o3), RoI-re-encoding ablations (Argus), and training-free zoom pipelines that add +8 to +35 points with no weight change.

### Cited Findings
- MED framework (Qwen2.5-VL-7B and Qwen3-VL-8B, GRPO, ~15K samples 80% from Thyme + Mini-o3, 1,600 steps, binary reward): tool contribution ratio S_tool = 0.30 (Qwen2.5-VL) and 0.22 (Qwen3-VL); "Over 70% of performance gains captured by intrinsic (tool-free) component"; no-tool RL tracks the tool-free accuracy of the tool-RL model within 0.0175/0.0191; final tool-free accuracy 0.644 / 0.678; the tool schema alone (present but execution forbidden) costs 5.8% / 13.0%; conclusion: RL "learns to coexist safely with tools rather than master them" — [Disentangling crop-and-zoom RL](https://arxiv.org/abs/2602.01334)
- Same paper, 370 persistent failures on Qwen2.5-VL: 271 no-call failures (82 should have called), 99 call failures = 52 wrong crops + 37 correct crop but wrong answer + 10 correct crop still hard; Call-Harm reduction, not Call-Gain, drives most of the RL improvement — [Disentangling crop-and-zoom RL](https://arxiv.org/abs/2602.01334)
- DeepEyes text-only RL CoT vs interleaved: HR-8K 60.8 vs 72.6 — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Simple o3 tool ablation on V*: `reuse` (re-insert original image) +4.8, `zoom_in` ≈ +1, `focus_area` (crop) +6.9 and +4.9 HR-4K — [Simple o3](https://arxiv.org/abs/2508.12109)
- Argus V*: implicit attention 58.6 → text-only box guidance 63.9 → RoI re-encoding 68.1; re-encoding beats re-sampling on small objects — [Argus](https://arxiv.org/abs/2505.23766)
- LFPC crop-dependence test: swapping predicted crops for GT crops changes V* by 3.2 (base), 11.0 (Stage-I), 18.5 (LFPC); replacing crops with random noise drops Stage-I models 5–10% but not DeepEyes, which shows "answer-first-crop-later" behaviour — [LFPC](https://arxiv.org/abs/2603.27494)
- Pixel Reasoner, zero-shot Qwen2.5-VL-7B: 20.2% of rollouts call a visual op, 40.6% of those error out, accuracy 23.2% with ops vs 49.5% textual — so the untrained model is worse with the tool than without — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- Size dependence without any tool (TextVQA, no-crop → human-crop): LLaVA-1.5 small objects 39.38 → 69.95, large 50.65 → 56.96; InstructBLIP small 21.79 → 69.60; BLIP-2 small 12.13 → 55.76 — [ViCrop](https://arxiv.org/abs/2502.17422)
- Training-free crop gains: ViCrop LLaVA-1.5-7B V* 42.41 → 62.30, TextVQA 47.80 → 56.06 — [ViCrop](https://arxiv.org/abs/2502.17422); ZoomEye LLaVA-v1.5-7B V* 48.68 → 83.25, LLaVA-OV-7B 75.39 → 90.58, InternVL2.5-8B 69.11 → 84.82; HR-8K InternVL2.5-8B 57.38 → 73.63 — [ZoomEye](https://arxiv.org/abs/2411.16044); Zoom-Refine InternVL3-78B +3.60 (MME-RW reasoning), +5.0 (HR-8K), InternVL3-2B +3.10 — [Zoom-Refine](https://arxiv.org/abs/2506.01663)
- Learned external zoom without touching the VLM: CropVLM (256M policy) on Qwen2.5-VL-3B at 448 px: V* +8.38 (59.69), HR-4K +13.25 (65.13), HR-8K +16.25 (60.75), DocVQA +14.89 — [CropVLM](https://arxiv.org/abs/2511.19820); Q-Zoom on Qwen2.5-VL-7B: V* 78.0 → 85.3, HR-8K 63.6 → 77.3 — [Q-Zoom](https://arxiv.org/abs/2604.06912)
- Downsampling is the mechanism: "accuracy significantly decreased with higher input resolution" and "visual information loss due to downsampling in HR images can be compensated by relevant textual information" — [HR-Bench/DC²](https://arxiv.org/abs/2408.15556)
- Zoom can hurt: noisy crops (IoU < 0.3) push accuracy below baseline (48.2 vs 53.6 simple; 47.1 vs 47.8 complex) — [Active-Look](https://arxiv.org/abs/2604.24396); unconditional zoom on ScreenSpot-v2 drops 81.84 → 77.20 — [UI-Zoomer](https://arxiv.org/abs/2604.14113); ZoomEye position tasks −12.95 on MME-RW — [ZoomEye](https://arxiv.org/abs/2411.16044); CoF v1 TextVQA 83.6 → 81.8 and Thyme OCRBench 88.4 → 86.3 — [CoF v1](https://arxiv.org/abs/2505.15436v1), [Thyme](https://arxiv.org/abs/2508.11630)
- Attribute vs spatial: Adaptive CoF V* attribute 73.9 → 92.2, spatial 67.1 → 86.4 — [Adaptive CoF](https://arxiv.org/abs/2505.15436); SpecEyes on DeepEyes: V* attribute 90.43 at 1.53× speedup, position 89.47 at 1.90× — [SpecEyes](https://arxiv.org/abs/2603.23483)

### Inferences
- The tool is unambiguously useful when it is the only route to pixels the encoder threw away (HR-Bench 8K, V* at ≤1024 px input); at native full resolution the marginal value shrinks to a few points and RL's benefit is mostly intrinsic.
- "Tool vs no tool at equal training" is answered by two papers (Disentangling; DeepEyes Table 9) and they disagree in emphasis: DeepEyes shows the interleaved image matters for 8K, the MED study shows most of the RL delta survives with the tool disabled. Both can be true: crops matter for ultra-high-res inputs and much less at 2M-pixel budgets.
- For attribute verification specifically (color/small text/parts), the reliable signal is that crop quality gates the gain; any pipeline that cannot guarantee IoU ≳ 0.3 with the target will lose to the global view.

### Gaps
- No paper reports a per-attribute breakdown (color vs text vs part) for tool vs no-tool at equal training; the V* attribute subset is the finest split available.
- The Disentangling paper's benchmark list beyond V*/HR-Bench/MME-RW was not captured in the extraction.

## Q2. What happens at 3B/4B/7B? Which recipes worked small, which needed 32B+?

### Takeaway
Everything in the core line was demonstrated at 7B (Qwen2.5-VL-7B), and nothing found required 32B+; at 2B–4B the working recipes are (a) external or training-free zoom around a frozen small model (CropVLM, ZoomEye, Zoom-Refine, RankGround, UI-Zoomer), (b) RL with a fixed/short tool schema and small data (MGPO-3B, ViGoRL-3B, Visual-ARFT-3B, OpenThinkIMG-2B, GUI-RCPO-3B, RC-GRPO on Qwen3-VL-4B with LoRA), while gains shrink roughly by half from 7B to 3B in the papers that report both.

### Cited Findings
- Visual-ARFT: MAT-Coding F1 +8.01 (3B) vs +18.56 (7B); Hard subset +10.44 vs +25.93; 3B still beats GPT-4o on MAT-Coding — [Visual-ARFT](https://arxiv.org/abs/2505.14246)
- ViGoRL 3B: V* 74.2 → 79.1 (7B: 78.0 → 86.4 with multi-turn zoom); ScreenSpot-Pro 23.9 → 31.1 (multi-turn 32.3); ScreenSpot-V2 68.4 → 86.5; SAT-2 46.1 → 62.9 — [ViGoRL](https://arxiv.org/abs/2505.23678)
- OpenThinkIMG on Qwen2-VL-2B: 29.56 → 59.39 on ChartGemma with 1,471 tool trajectories + 500 GRPO steps on 4–8 A100 — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)
- MGPO "also tested on 3B variant" (numbers not extracted) — [MGPO](https://arxiv.org/abs/2507.05920)
- ZoomEye (training-free) on Qwen2.5-VL-3B "outperforms Pixel Reasoner on both benchmarks, even with smaller backbone" (Qwen2.5-VL-3B vs 7B) — [ZoomEye](https://arxiv.org/abs/2411.16044)
- Zoom-Refine (training-free) gains grow as models shrink: InternVL3-14B +2.42, 8B +2.71, 2B +3.10 (MO task +13.05) — [Zoom-Refine](https://arxiv.org/abs/2506.01663)
- CropVLM: 256M crop policy, 3 GPU-h SFT + 24 GPU-h GRPO on one A100 per resolution; on Qwen2.5-VL-3B V* +8.38, HR-4K +13.25, HR-8K +16.25; on LLaVA-1.5-7B V* +8.38, HR-4K +6.13; policy adds 418–691 ms and ≤1.7 GB, vs ViCrop grad-attn 525 ms and 19.3 GB — [CropVLM](https://arxiv.org/abs/2511.19820)
- RankGround: 2B grounders on ScreenSpot-Pro 35.4–48.1 → 52.8–64.7 (+16.6–17.3); Qwen3-VL-2B on UI-Vision 18.88 → 49.00; peak memory 8.6 GB (2B) / 21.2 GB (8B) — [RankGround](https://arxiv.org/abs/2609.18690)
- GUI-RC/RCPO on Qwen2.5-VL-3B: ScreenSpot-Pro +2.52 (test-time voting), ScreenSpot-v2 +1.49 (RC) vs +5.50 (RCPO, 40 GRPO steps on 1,272 unlabeled images, 8×A100) — [GUI-RC](https://arxiv.org/abs/2508.05615)
- RC-GRPO for no-target REC: LoRA on Qwen3-VL-4B, Qwen2.5-VL-7B and MiniCPM-V, 2,000 samples, 500 steps on 2×A800 — [RC-GRPO](https://arxiv.org/abs/2608.04698)
- UI-Zoomer evaluated Qwen2.5-VL-3B (numbers not extracted); Q-Zoom and Active-Look evaluated Qwen3-VL-4B (numbers not extracted) — [UI-Zoomer](https://arxiv.org/abs/2604.14113), [Q-Zoom](https://arxiv.org/abs/2604.06912), [Active-Look](https://arxiv.org/abs/2604.24396)
- Contrastive curriculum was replicated on Gemma 4 E4B and InternVL 3.5-8B; Gemma needed hard negatives only (τ_max = 0) — [Contrastive zoom](https://arxiv.org/abs/2609.03206)
- 32B: DeepEyes supports Qwen2.5-VL-32B but needs ≥64 GPUs — [DeepEyes GitHub](https://github.com/Visual-Agent/DeepEyes); Qwen3-VL reports V* 93.7 only at 235B-A22B — [Qwen3-VL report](https://arxiv.org/abs/2511.21631)
- Cold start is what a small model lacks: Mini-o3 without SFT collapses to 25.4% on VisualProbe-hard; DeepEyesV2 direct RL abandons code — [Mini-o3](https://arxiv.org/abs/2509.07969), [DeepEyesV2](https://arxiv.org/abs/2511.05271)

### Inferences
- At ≤4B the cheapest reliable win is an external zoom (training-free or a 256M policy) rather than teaching the small model itself to call tools; the CropVLM numbers on Qwen2.5-VL-3B are larger than any 3B tool-RL result found.
- If the small model must call the tool, the recipes that worked at 2–3B share a short, fixed schema (single crop / two-turn / one code block) and ≤2K cold-start examples; the open-ended 6–32-turn Mini-o3 style has no sub-7B demonstration.

### Gaps
- No paper found trains a 4B model (Qwen3-VL-4B / Gemma 4 E4B / InternVL3.5-4B) with a crop tool and reports V*/HR-Bench; the 4B evidence is REC-refusal (RC-GRPO) and training-free wrappers.
- MGPO-3B, ZoomEye-3B and UI-Zoomer-3B numbers exist in the papers but were not captured.

## Q3. How are tool trajectories obtained without human labels, and how many?

### Takeaway
Three routes dominate: GT boxes from segmentation/detection sets (SA-1B, V*, RefCOCO-family) turned into synthetic crops via templates or an agent; distillation from a larger model (GPT-4o/4.1, Gemini 2.5, Claude Sonnet 4, Qwen2.5-VL-72B) with real tool execution and answer-verified rejection sampling; or no trajectories at all with the tool forced by a template or kept alive by a reward. Working sizes range from 20 examples to 500K, with 1.5K–7.5K sufficient for 7B when RL follows.

### Cited Findings
- 0 trajectories: DeepEyes (47K RL prompts, perception-utility filter uses GT regions) — [DeepEyes](https://arxiv.org/abs/2505.14362); MGPO (fixed two-turn template, 21,690 prompts, no boxes) — [MGPO](https://arxiv.org/abs/2507.05920); contrastive curriculum (6,698 queries, negatives auto-generated at controlled IoU) — [Contrastive zoom](https://arxiv.org/abs/2609.03206); LFPC (information-gap tuples + 256 annotated boxes) — [LFPC](https://arxiv.org/abs/2603.27494)
- 20–1.5K: Visual-ARFT 20 hand-written search examples and 1,200 synthetic-distortion coding examples — [Visual-ARFT](https://arxiv.org/abs/2505.14246); OpenThinkIMG 1,471 GPT-4o trajectories — [OpenThinkIMG](https://arxiv.org/abs/2505.08617)
- 3K–12K: CoF 3K (360 SA-1B images, GPT-4.1 questions, GPT-4.1-mini agent with Locate/Understand/Adjust/Verify tools; later 5K) — [CoF v1](https://arxiv.org/abs/2505.15436v1), [Adaptive CoF](https://arxiv.org/abs/2505.15436); Mini-o3 ~6K from 6 exemplars by few-shot prompting, correct-answer filter — [Mini-o3](https://arxiv.org/abs/2509.07969); Pixel Reasoner 7.5K GPT-4o template trajectories from SA1B/FineWeb/STARQA with error-induced self-correction — [Pixel Reasoner](https://arxiv.org/abs/2505.15966); VLM-R³ 11,810 from Qwen2.5-VL-72B + DeepSeek-V3 coherence check — [VLM-R³](https://arxiv.org/abs/2505.16192); Qwen3-VL ~10K two-turn grounding examples — [Qwen3-VL report](https://arxiv.org/abs/2511.21631)
- 30K–146K: ViGoRL 1,500 prompts → ~30K MCTS traces with Qwen2.5-VL-72B (direct + corrected chains; distilling without MCTS gave −2.32 BLINK OOD) — [ViGoRL](https://arxiv.org/abs/2505.23678); Simple o3 150K → ~100K Gemini-2.5-Flash traces after two verifiers — [Simple o3](https://arxiv.org/abs/2508.12109); VITAL 72K CoT + 110K RL with tool parameters = GT + 20% noise — [VITAL](https://arxiv.org/abs/2508.04416)
- 400K–500K: Thyme 500K incl. 28K V* GT-box crops, 14K rotations, 10K enhancements, code verified by execution then by Qwen2.5-VL-72B then by two human screeners — [Thyme](https://arxiv.org/abs/2508.11630); V-Thinker 400K + 40K from GPT-5 — [V-Thinker](https://arxiv.org/abs/2511.04460); Argus 3.8M SFT with GT boxes — [Argus](https://arxiv.org/abs/2505.23766)
- Multi-teacher with executed tools: DeepEyesV2 uses Gemini 2.5 Pro, GPT-4o, Claude Sonnet 4 and feeds real tool outputs back, keeping only prompts the base answers ≤2/N times — [DeepEyesV2](https://arxiv.org/abs/2511.05271)
- Learned proposer without boxes: CropVLM SFT on Qwen2.5-VL-7B synthetic boxes then GRPO with answer accuracy or GT-answer log-likelihood — [CropVLM](https://arxiv.org/abs/2511.19820); InSight-o3 15,303 synthetic collages (Visual CoT + V*) with in-loop pseudo-IoU + outcome reward, and 10,186 InfographicVQA layout boxes with IoU reward — [InSight-o3](https://arxiv.org/abs/2512.18745)
- Self-supervised pseudo-labels from attention: Q-Zoom ~185K samples from the MLLM's own cross-attention maps — [Q-Zoom](https://arxiv.org/abs/2604.06912)

### Inferences
- Answer-verified rejection sampling is the universal filter; box-level supervision is used to build the prompt set (which items need a crop) far more often than to supervise the crop itself.
- The error-induced self-correction trick (Pixel Reasoner) and MCTS backtracking traces (ViGoRL) are the two documented ways to teach recovery from a bad crop, and both reported measurable OOD gains over plain distillation.

### Gaps
- DeepEyesV2's cold-start size is not stated in the extracted text.
- No paper reports a data-scaling curve for trajectory count vs V* gain.

## Q4. Failure modes and fixes

### Takeaway
The reported failure modes are: RL collapse to no-tool (every paper that tried plain outcome RL), reward hacking with placeholder or unnecessary tool calls, over-use early in RL, unfaithful crops that the answer does not depend on, context/turn collapse from token budgets, and 3–30× latency; fixes are correctness-conditioned tool bonuses, curiosity bonuses with caps, penalties for unnecessary zooms, forced-turn templates, over-turn masking with reduced pixel budgets, consistency/contrastive/grounding rewards, and gated (uncertainty-triggered) zooming.

### Cited Findings
- Collapse to no-tool: without the conditional tool reward "the model quickly reduces and stops performing perception actions" — [DeepEyes](https://arxiv.org/abs/2505.14362); Pixel Reasoner "learning trap": zero-shot RaPR falls from ~20% to 0%, fixed by curiosity bonus H = 0.3 that fades as RaPR rises — [Pixel Reasoner](https://arxiv.org/abs/2505.15966); correctness+format-only RL "degrades performance; model avoids zoom-in" — [Adaptive CoF](https://arxiv.org/abs/2505.15436); direct RL "abandons code generation" and converges to one placeholder code block — [DeepEyesV2](https://arxiv.org/abs/2511.05271); GRPO without the template keeps valid-coordinate rate low — [MGPO](https://arxiv.org/abs/2507.05920)
- Turn collapse: 12M max pixels → 1.0 avg turn and 36.1% vs 48.0% at 2M; no over-turn masking → 3.0 turns and 32.2% vs 44.4% — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Over-use then self-correction: DeepEyes stages — steps 0–20 rising action count with low grounding IoU, 20–45 over-querying, 45–80 fewer calls — [DeepEyes](https://arxiv.org/abs/2505.14362); tool calls/sample 0.63 → 0.10–0.12 — [OpenThinkIMG](https://arxiv.org/abs/2505.08617); LFPC Stage-I ~10–12 calls/question vs ~4.5 baseline, reduced by grounding reward — [LFPC](https://arxiv.org/abs/2603.27494); Thyme: code for "0.5 × 9", variable confusion; a code reward "encourages unnecessary code" — [Thyme](https://arxiv.org/abs/2508.11630)
- Unfaithful crops: DeepEyes unaffected by noise-replaced crops ("answer-first-crop-later") — [LFPC](https://arxiv.org/abs/2603.27494); Thyme crops the wrong area yet answers correctly — [Thyme](https://arxiv.org/abs/2508.11630); bbox IoU "correlates poorly with VQA accuracy" — [CropVLM](https://arxiv.org/abs/2511.19820); 52 of 99 called failures were wrong crops — [Disentangling](https://arxiv.org/abs/2602.01334); ignored execution errors and "reward-hacking loop" claiming success — [Pixel Reasoner](https://arxiv.org/abs/2505.15966)
- Reward hacking of learned tool rewards: contrastive reward exploited via longer second reasoning, lexical overlap, round pixel values; fixed by hard-negative curriculum τ_max ∈ [0.15, 0.20] — [Contrastive zoom](https://arxiv.org/abs/2609.03206); process reward "subjective and hackable" — [Thyme](https://arxiv.org/abs/2508.11630)
- Multi-turn RL pathologies: coordinate repetition, skipping tool use, tag violations; fixed with +0.2 diversity reward per distinct coordinate — [ViGoRL](https://arxiv.org/abs/2505.23678)
- Error propagation without backtracking: DiMo-GUI "early-stage mistakes ... irrecoverable"; accuracy by max iterations 18.4/18.7/40.2/46.7/48.8/48.9 for 0–5 — [DiMo-GUI](https://arxiv.org/abs/2507.00008); GUI-Lens verification rejects crops that omit the target and restores the full screen — [GUI-Lens](https://arxiv.org/abs/2608.03270)
- Latency: MME-RW reasoning wall-clock 128 min baseline vs 414 TextCoT vs 447 Zoom-Refine vs 3,572 ZoomEye vs 3,790 DC² — [Zoom-Refine](https://arxiv.org/abs/2506.01663); 12.4 s (DeepEyes) vs 2.8 s (LFPC) per HR-8K image — [LFPC](https://arxiv.org/abs/2603.27494); 10-day → 3-day training by capping turns — [Mini-o3](https://arxiv.org/abs/2509.07969); always-zoom inflates ScreenSpot-v2 from 35:47 to 6:43:07 — [UI-Zoomer](https://arxiv.org/abs/2604.14113); speculative tool-free answering gives 1.73× (DeepEyes) / 1.42× (Thyme) at ~84% accuracy but only 0.95–1.13× on HR-Bench — [SpecEyes](https://arxiv.org/abs/2603.23483); +66.8% per WebVoyager trajectory, +180% on ScreenSpot-Pro for 72B — [RegionFocus](https://arxiv.org/abs/2505.00684)
- Under-use at inference: vSearcher averages ~1 crop per task "despite encouragement" — [InSight-o3](https://arxiv.org/abs/2512.18745); 271 of 370 persistent failures made no call — [Disentangling](https://arxiv.org/abs/2602.01334)
- Fix catalogue with weights: conditional bonus (DeepEyes; LFPC; V-Thinker λ₂ = 0.3) — [DeepEyes](https://arxiv.org/abs/2505.14362), [V-Thinker](https://arxiv.org/abs/2511.04460); α = 0.5 curiosity, β = 0.05 per extra op — [Pixel Reasoner](https://arxiv.org/abs/2505.15966); δ = 0.2 penalty for unnecessary zoom — [Adaptive CoF](https://arxiv.org/abs/2505.15436); consistency reward ×0.5 — [Thyme](https://arxiv.org/abs/2508.11630); IoU/L1 geometric reward with coverage gate 0.9 — [LFPC](https://arxiv.org/abs/2603.27494); uncertainty gate routing only 3–10% of samples to zoom — [UI-Zoomer](https://arxiv.org/abs/2604.14113); stop when consecutive predictions move < 1/6 of the diagonal, max 7 iterations — [DiMo-GUI](https://arxiv.org/abs/2507.00008)

### Inferences
- The single most consistent finding is that plain outcome reward kills the tool; the correctness-conditioned bonus is the cheapest fix, but it does not make crops faithful (DeepEyes passes the noise test), so a geometric or contrastive term is needed if crop quality matters downstream.
- Latency scales with agentic depth, so a one-call design (contrastive curriculum, MGPO, Zoom-Refine, LFPC) captures most of the accuracy at a fraction of the cost of tree search or 16–32-turn loops.

### Gaps
- No paper quantifies "unfaithful crop" rates for the final released checkpoints of Mini-o3 or Thyme.
- Latency in seconds per query for a 7B agentic model on a single consumer GPU is not reported anywhere found.

## Q5. Zoom/crop for referring-expression grounding, no-target rejection, and GUI grounding

### Takeaway
For GUI grounding the evidence is dense and positive: training-free or lightly trained zoom/crop pipelines add +10 to +31 points on ScreenSpot-Pro across 3B–72B models, with adaptive gating avoiding losses on low-resolution screens; for natural-image REC the evidence is thin (Argus reaches RefCOCO 89.8 with grounded CoT; DeepEyes' REC gain is ≤1 point and unverified), and no-target rejection has been attacked with refusal-calibrated RL (no crop tool) and with box-wise True/False verification (zero-shot, crop-marked candidates, explicit abstain).

### Cited Findings
- GUI, training-free zoom: RegionFocus (four fixed crop ratios around a focal point, image-as-map landmarks): ScreenSpot-Pro Qwen2.5-VL-72B 47.8 → 61.6, UI-TARS-72B 38.1 → 50.2, UI-TARS-7B 35.7 → 41.2, Qwen2.5-VL-7B 26.8 → 32.1; WebVoyager UI-TARS-72B 44.1 → 59.5 — [RegionFocus](https://arxiv.org/abs/2505.00684); DiMo-GUI (half-size crops centered on prediction, text/icon split): OS-Atlas-7B 18.9 → 49.7, UGround-V1-7B 31.4 → 47.4; ScreenSpot-v2 82.5 → 85.7, 87.6 → 89.2 — [DiMo-GUI](https://arxiv.org/abs/2507.00008)
- GUI, uncertainty-gated zoom: UI-Zoomer (8 samples at T = 0.9, gate = mean pairwise IoU + token confidence, crop radius from prediction variance, min side 512 px, ≤2 passes): ScreenSpot-Pro Qwen2.5-VL-7B 27.6 → 41.0, GUI-G2-7B 48.7 → 61.4, UI-Venus-7B 50.0 → 61.8, UI-Venus-72B 59.2 → 67.8; UI-Vision 13.3 → 23.6 (7B); ScreenSpot-v2 87.2 → 91.4; adaptive crop 61.80 vs fixed ratios 0.8/0.5/0.3 = 55.22/59.58/61.35; icons gain more than text (+12.5 vs +11.1) — [UI-Zoomer](https://arxiv.org/abs/2604.14113)
- GUI, VLM-chosen coarse-to-fine crops with verification: GUI-Lens GPT-5.5 ScreenSpot-Pro 94.2 text / 77.8 icon, ScreenSpot-v2 96.8, UI-Vision 91.52; removing cropping −10.4 (GPT-5.5), −41.3 (Claude Opus 4.7), −15.6 (MiniMax-M3); 95.1% finish within 4 crop rounds; "Efficient" +10.34 points at 1.27× latency — [GUI-Lens](https://arxiv.org/abs/2608.03270)
- GUI, reranker-selected crop: RankGround (9 overlapping tiles, Qwen3-VL-Reranker-2B LoRA r16 trained on 6,789 ViSurf instances, strict containment labels): ScreenSpot-Pro 8B 48.7–58.9 → 64.3–71.0 (ZoomIn baseline 60.0–69.0); OSWorld-G UI-Venus-1.5-8B 74.71 → 78.04 (ZoomIn 72.55); ScreenSpot-v2 96.31 → 95.36 (slight loss); Hit@1 88.2% with icon errors 19.9% vs text 5.5%; 625–959 ms end-to-end; oracle coverage 99.75% — [RankGround](https://arxiv.org/abs/2609.18690)
- GUI, RL-trained grounded reasoning: ViGoRL multi-turn zoom ScreenSpot-Pro 3B 32.3, 7B 33.1 (base 23.9 / 29.0); ScreenSpot-V2 7B 91.0 — [ViGoRL](https://arxiv.org/abs/2505.23678); GUI-RCPO +3–6 on ScreenSpot-v2 from unlabeled screenshots — [GUI-RC](https://arxiv.org/abs/2508.05615)
- Natural-image REC with grounded CoT: Argus RefCOCO val 89.8, RefCOCO+ val 84.7, RefCOCOg test 85.2; V* 78.5 multi-RoI — [Argus](https://arxiv.org/abs/2505.23766); CoF grounding accuracy 0.82 → 0.86 after RL — [CoF v1](https://arxiv.org/abs/2505.15436v1); MGPO crops sufficient for the answer 65.2% vs 47.1% — [MGPO](https://arxiv.org/abs/2507.05920); LFPC crop IoU 29.8 → 34.5 (FSP) — [LFPC](https://arxiv.org/abs/2603.27494); DeepEyes RefCOCO +0.6–1.0 **[unverified]** — [DeepEyes](https://arxiv.org/abs/2505.14362)
- Small-object detection via learned region proposals: SODA-D AP_s 8.0 → 15.1, AR_s 8.7 → 22.0 — [Active-O3](https://arxiv.org/abs/2505.21457)
- No-target rejection (no tool): RC-GRPO rewards +1 IoU≥0.5 / 0 / −1 for "None" on positives and +1 for "None" on negatives, forced-rejection rollouts, negative-advantage scaling α = 0.5; Qwen2.5-VL-7B on FineCops-Ref: Pr 56.4 (P-acc 73.6, N-acc 5.3) → 67.4 (69.6, 61.1); SFT reaches N-acc 95.4 but P-acc 30.1 (over-refusal); gRefCOCO vanilla GRPO 62.5 vs RC-GRPO-I 66.6; 2,000 training samples, LoRA, 2×A800, 500 steps; also Qwen3-VL-4B — [RC-GRPO](https://arxiv.org/abs/2608.04698)
- Ground-then-verify with candidate boxes (zero-shot): YOLO-World proposals, each rendered with only that box and asked "Does this box match the description?", tie-break by overlay-and-index, abstain when all False; GPT-5 RefCOCO/+/g val 79.3 / 74.2 / 72.4 vs single-shot selection 70.1 / 66.7 / 69.7 and vanilla GPT-5 grounding <15%; 2–3 VLM calls per query; bounded by proposal recall — [T/F verification REC](https://arxiv.org/abs/2509.09958)
- Hallucination-aware zoom: Active-Look zooms only "doubtful" proposals (detector disagreement, 38% of samples): POPE-adv LLaVA-1.5-7B 76.10 → 80.55, Qwen3-VL-8B 84.32 → 89.26; CHAIR_s 53.0 → 15.0; 2.3× runtime — [Active-Look](https://arxiv.org/abs/2604.24396)
- Search-then-reason split: InSight-o3 vSearcher (Qwen2.5-VL-7B, hybrid IoU + outcome RL) lifts GPT-5-mini V* 80.6 → 86.9 and HR-4K 72.0 → 86.7, but Gemini-2.5-Flash HR-4K 83.5 → 82.3 and MME-RW 56.5 → 56.3 — [InSight-o3](https://arxiv.org/abs/2512.18745)

### Inferences
- The GUI results are the best model for "zoom-then-ground": a coarse guess, a crop of 30–50% of the screen (or a 512-px minimum square), one re-ground, and a gate so that low-resolution screens are not re-cropped; every method that always zooms loses on ScreenSpot-v2.
- For rejection, the crop tool is not what fixes it; the documented lever is the reward asymmetry (RC-GRPO) or a per-candidate yes/no verifier with an abstain path (T/F verification), which is the same structure as "per-candidate verification" in the user's hard-sample plan.
- Combining the two is untested: no paper found trains a model to crop a candidate and then answer "is this the referent" with a no-target option on natural images.

### Gaps
- No RefCOCO/gRefCOCO numbers for DeepEyes, Mini-o3, Thyme, CoF or Pixel Reasoner were found; the REC effect of crop-tool RL on natural images is essentially unmeasured.
- No hard-negative / rejection benchmark (HumanRef, gRefCOCO no-target, GroundingME) result exists for any crop-tool model found.

## Q6. Alternatives to a learned tool: fixed crop-and-re-ask pipelines and how they compare

### Takeaway
Training-free pipelines (attention crops, tree search, box-then-refine, divide-and-conquer) and cheap external policies recover most or all of the tool-RL gain on V*/HR-Bench at 7B (ZoomEye 90.6 on LLaVA-OV-7B, Zoom-Refine +5 HR-8K at 78B, CropVLM +16 HR-8K at 3B, Q-Zoom +13.7 HR-8K at 7B) and frequently beat the RL models on cost; their weaknesses are latency for search-based methods, no backtracking for greedy zoom, and dependence on a good initial localization.

### Cited Findings
- ViCrop (rel-att / grad-att / pure-grad crops from the model's own attention, crop concatenated with the full image): LLaVA-1.5-7B V* 42.41 → 62.30, TextVQA 47.80 → 56.06, POPE 85.27 → 87.25; overhead 0.89–1.16 s ≈ 5 answer tokens; weak on relations and counting — [ViCrop](https://arxiv.org/abs/2502.17422)
- ZoomEye (quad-tree, existing/latent confidence priorities, stop when answer confidence > τ 0.6–0.8): LLaVA-OV-7B V* 75.39 → 90.58, HR-4K 63.00 → 69.63, HR-8K 59.75 → 69.25; InternVL2.5-8B HR-8K 57.38 → 73.63; avg 5–8 search steps; MME-RW position −12.95; document tasks "less applicable" — [ZoomEye](https://arxiv.org/abs/2411.16044)
- Zoom-Refine (answer → predict normalized box → crop from original → re-answer with history): InternVL3-78B HR-4K +4.2, HR-8K +5.0, MME-RW reasoning +3.60; beats ZoomEye by +2.92 and DC² by +2.87 on MME-RW reasoning at 447 vs 3,572 / 3,790 minutes — [Zoom-Refine](https://arxiv.org/abs/2506.01663)
- DC² (recursive split, per-patch captions, hallucination filtering by cross-layer intersection, text retrieval α = 0.3): LLaVA-1.5-7B HR-8K 32.1 → 42.3, HR-4K 36.1 → 50.0, V* 46.2 → 57.3; InternVL-1.5-26B HR-8K 57.9 → 61.3; 2.8–4.6 samples/min — [HR-Bench/DC²](https://arxiv.org/abs/2408.15556)
- Chain-of-Spot (trained two-round ROI-then-answer, ROI labels from detector relevance maps, 3.3M QA): LLaVA-1.5-13B VizWiz 53.6 → 58.0, TextVQA 61.3 → 62.4, GQA 63.3 → 64.8, MM-Vet 35.4 → 37.6 — [Chain-of-Spot](https://arxiv.org/abs/2403.12966)
- SEAL / V* (2023 baseline): separate search model, 4.65 steps and 6.0 s per target on an A100; V* 75.39 vs GPT-4V 54.97 — [V*/SEAL](https://arxiv.org/abs/2312.14135)
- External crop policy: CropVLM beats ViCrop and UV-CoT on V* for LLaVA-1.5 (50.79 vs 49.21 / 43.98) and on TextVQA for Qwen2.5-VL-3B (75.72 vs 74.15 / 74.56) with ≤1.7 GB extra memory — [CropVLM](https://arxiv.org/abs/2511.19820)
- Feature-space routing: Q-Zoom (gating network + self-distilled RPN inside one prefill) V* 78.0 → 85.3, HR-8K 63.6 → 77.3, 4.39× speedup with 73.2% fewer tokens; 72.3 vs DeepEyes 71.1 on HR-Bench at 0.86× baseline throughput; adds +5–6 on top of RL thinking models — [Q-Zoom](https://arxiv.org/abs/2604.06912)
- Head-to-head, training-free vs RL: ZoomEye on Qwen2.5-VL-3B beats Pixel Reasoner 7B — [ZoomEye](https://arxiv.org/abs/2411.16044); one-call contrastive model matches Mini-o3 at 16 calls — [Contrastive zoom](https://arxiv.org/abs/2609.03206); LFPC 2.8 s vs DeepEyes 12.4 s — [LFPC](https://arxiv.org/abs/2603.27494)
- Multi-crop ensembles in GUI: RankGround's MVP baseline (3+ VLM calls, 2,342–4,648 ms) vs reranker 625–959 ms — [RankGround](https://arxiv.org/abs/2609.18690)
- Failure of greedy pipelines: DiMo-GUI has "no error correction or backtracking" — [DiMo-GUI](https://arxiv.org/abs/2507.00008); Zoom-Refine has "localization dependency" — [Zoom-Refine](https://arxiv.org/abs/2506.01663); Active-Look "erroneous visual evidence can dominate subsequent reasoning" — [Active-Look](https://arxiv.org/abs/2604.24396)

### Inferences
- A two-pass "predict box → crop from the original → re-answer with both views" (Zoom-Refine / MGPO-template / UI-Zoomer shape) is the Pareto point across natural images and GUIs: ≤2 extra passes, +3–13 points, no training or a few hundred RL steps.
- The learned-tool papers' advantage over these pipelines is smallest exactly where the base model already localizes well; it is largest on VisualProbe-style search tasks (Mini-o3 48.0 vs DeepEyes 35.1 hard), which are multi-hop search problems rather than verification problems.

### Gaps
- No paper found runs a fixed multi-crop ensemble (e.g., top-k detector boxes each re-asked) on V*/HR-Bench with a 2025 base model; DC² is the closest and is 2024-era LLaVA.

## Q7. Feasibility on one 32 GB GPU with a 4B model (LoRA), and inference cost per query

### Takeaway
Inference-time zoom (training-free or with a 256M external policy) fits comfortably on 32 GB with a 4B model at roughly 2–4 passes and 0.4–3 s per query; LoRA GRPO for a short fixed-schema tool (two-turn, one crop) at 4B is supported by two published single-node LoRA runs (CoF SFT LoRA r32 on 4×A100; RC-GRPO on Qwen3-VL-4B on 2×A800), whereas the open-ended 6–32-turn, 32K-context recipes (Mini-o3, DeepEyes with 16 rollouts × 20K tokens on ≥32 GPUs) are out of reach on one card.

### Cited Findings
- Published single-node LoRA runs: CoF SFT LoRA rank 32, 3 epochs, 4×A100 ~6 h; RL 8×A100 ~32 h — [Adaptive CoF](https://arxiv.org/abs/2505.15436); RC-GRPO LoRA on Qwen3-VL-4B, 2,000 samples, 500 steps on 2×A800 — [RC-GRPO](https://arxiv.org/abs/2608.04698); CropVLM 256M policy: 3 GPU-h SFT + 24 GPU-h GRPO on a single A100 — [CropVLM](https://arxiv.org/abs/2511.19820); GUI-RCPO 40 GRPO steps on 1,272 images, 8×A100 — [GUI-RC](https://arxiv.org/abs/2508.05615)
- Large-scale requirements: DeepEyes ≥32 GPUs for 7B, 256 prompts × 16 rollouts, 20,480-token responses — [DeepEyes GitHub](https://github.com/Visual-Agent/DeepEyes), [DeepEyes](https://arxiv.org/abs/2505.14362); Mini-o3 32K context, 16 samples/query, 6 turns, 2M pixels/image — [Mini-o3](https://arxiv.org/abs/2509.07969); Pixel Reasoner 8×A800 × 20 h — [Pixel Reasoner](https://arxiv.org/abs/2505.15966); Active-O3 8 GPUs × 24 h — [Active-O3](https://arxiv.org/abs/2505.21457); LFPC 416 A100-h — [LFPC](https://arxiv.org/abs/2603.27494); contrastive curriculum 8×A100 ~35 h/epoch, +46% over no-tool RL — [Contrastive zoom](https://arxiv.org/abs/2609.03206); Thyme 32×H800; V-Thinker 512 H20 — [Thyme](https://arxiv.org/abs/2508.11630), [V-Thinker](https://arxiv.org/abs/2511.04460)
- Inference cost per query: ViCrop 0.89–1.16 s GPU overhead — [ViCrop](https://arxiv.org/abs/2502.17422); CropVLM 418–691 ms on an RTX A6000 with 1.2–1.7 GB peak for the policy (ViCrop grad-attn on Qwen 19.3 GB) — [CropVLM](https://arxiv.org/abs/2511.19820); RankGround 625–959 ms with 21.2 GB peak for an 8B grounder + 2B reranker, 8.6 GB for 2B — [RankGround](https://arxiv.org/abs/2609.18690); Zoom-Refine ≈3.5× baseline wall-clock (447 vs 128 min) — [Zoom-Refine](https://arxiv.org/abs/2506.01663); LFPC 2.8 s vs DeepEyes 12.4 s per HR-8K image — [LFPC](https://arxiv.org/abs/2603.27494); Active-Look 2.3× with ~2,100–2,800 tokens total — [Active-Look](https://arxiv.org/abs/2604.24396); SEAL 6.0 s per target on A100 — [V*/SEAL](https://arxiv.org/abs/2312.14135); Argus RoI re-encoding 827 ms vs re-sampling 492 ms — [Argus](https://arxiv.org/abs/2505.23766); UI-Zoomer routes 3–10% of samples to the second pass — [UI-Zoomer](https://arxiv.org/abs/2604.14113)
- Token cost of a crop: Argus re-encoding adds 1,024 tokens per RoI — [Argus](https://arxiv.org/abs/2505.23766); Adaptive CoF uses 5.4% of DeepEyes' visual tokens on HR-4K — [Adaptive CoF](https://arxiv.org/abs/2505.15436); Mini-o3 caps 2M pixels per image — [Mini-o3](https://arxiv.org/abs/2509.07969)
- Qwen3-VL-4B ships with two-stage tool training and [0,1000] coordinates, so a 4B base with native crop-tool priors exists — [Qwen3-VL report](https://arxiv.org/abs/2511.21631)

### Inferences
- Local (RTX 5090, 32 GB VRAM, 32 GB RAM) inference plan: a 4B model in bf16 (~8 GB weights) plus one crop re-encoded at ≤1M pixels (~1.3K tokens at 28-px patches) stays well under 32 GB even with two views in context; expect ~2–4 forward passes and ~1–3 s per query on the Zoom-Refine/MGPO-template pattern, and ~0.5 s extra if a 256M CropVLM-style proposer is used instead of the 4B model's own box.
- Local LoRA GRPO is plausible only for a fixed two-turn schema with ≤4 rollouts of ≤4K tokens at ≤1M pixels; at 16 rollouts × 20K tokens (DeepEyes) or 32K contexts with 6 turns (Mini-o3) the KV cache alone exceeds the card, so those recipes belong on rented multi-GPU nodes.
- Because >70% of the tool-RL gain was intrinsic in the MED study, a local kill test should first measure the 4B model with a training-free two-pass crop (no training) against its full-resolution single pass; if that gap is small on the target data, the RL tool recipe is unlikely to pay for itself.

### Gaps
- No paper reports peak VRAM for LoRA GRPO of a 3–4B VLM with a multi-image crop tool; the memory estimates above are my inferences, not measurements.
- No per-query latency on consumer GPUs (RTX 40/50 series) is published for any agentic zoom model.
